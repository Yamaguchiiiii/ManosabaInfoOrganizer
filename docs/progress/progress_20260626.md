## 3. 🔧 残っている課題（次に対処する候補）

### 3-1. アニメの Edge 残カクツキ（軽微）
Chrome/Tauri(WebView2) は滑らか。**WebView2＝Edgeエンジンが滑らかな以上、コードは十分高速**で、
Edgeブラウザの余力不足（効率モード/拡張/多タブ）が主因。さらに詰めるなら Chrome/Edge の
DevTools Performance 録画で残コスト（描画 or GC）を特定 → 必要なら描画レイヤー構成の見直し。

### 3-2. 複数/複雑Syncの時刻ズレ ✅ 対応済み（要live検証）
旧: **相手キャラ側の到達時刻が `indexOf`(最初の訪問)固定**で、同一地点を複数回通る複雑Syncでズレた。
対応: `getNodeArrivalOccurrences` を新設し、相手キャラがその地点を通る**全訪問**の到達時刻を取得。
`handleSyncTime` で「**自分の自然到達時刻に最も近い訪問**」を合流点に選ぶよう変更（最も近い訪問＝
相手の他の予定を壊しにくい）。`handleMergeConfirm` の同行範囲も選んだ訪問以降に揃えた。
単一訪問のキャラは従来と同一挙動（影響は複数訪問キャラのみ）。
→ `utils/animationUtils.ts`(新関数), `CreateView.tsx`, `modals/MergeModal.tsx`(型に `pathIndex`)。
※自分側アンカーは既にオカレンス対応済み。これで自他ともオカレンス対応。要実機検証。

### 3-3. Sync UI の全面再設計（`_symptoms 05/20 #2`・`06/21 #6`）
