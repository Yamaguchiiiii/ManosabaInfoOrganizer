## 3. 🔧 残っている課題（次に対処する候補）

### 3-1b. アニメのカクツキ再発 → ★真因特定・修正（最重要）
セッション後半、Chromeでカクツキ再発（Tauriは正常）。Performance採取で **`setItem`/`put`(IndexedDB)
が100%**、heap 400MB の階段状増減。真因は **Zustand `persist` が全 `useAppStore.setState` で
全state を IndexedDB に書く**こと。再生ループが `currentTime` を約15回/秒 store に書くため、
保存データ増大に伴い毎フレーム巨大state書き込み→フレーム落ち＋GC圧（cache/LERPは無関係）。
**修正**: `currentTime`/`isPlaying`/`playbackSpeed` を永続化しない別ストア `usePlaybackStore` へ分離
（`store.ts`/`useAnimationPositions.ts`/`AnimationTimeline.tsx`）。再生がIndexedDBに触れなくなった。
詳細は `stutter_bisect_20260626.md`。要live再検証（Performanceで setItem が消えるか）。
※派生メモ: ノートのドラッグ等、他の高頻度 `setState` も persist を毎回叩く構造は残る（別途検討）。

### 3-1c. ノート編集の persist 書き込み最適化（3-1bの続き）✅
ノートはオブジェクトを `onDragEnd`/`onTransformEnd` で1回ずつ store にコミットするが、
1編集ごとに巨大 state を IndexedDB へ書くため、ドロップ時にヒッチ（＋`saveNoteHistory` で
partialize除外だけ変わる冗長書き込みも発生）。`idbStorage.setItem` を以下に変更（`store.ts`）:
- **直列化結果が前回と同一なら書かない**（履歴保存など除外キーのみの変更を無視）
- **異なる場合も 500ms debounce して最後の値を1回だけ書く**（連続編集を集約）
- タブ非表示/離脱(`visibilitychange`/`pagehide`)で**ベストエフォートflush**（取りこぼし対策）
トレードオフ: クラッシュ時に直近〜500msの編集が失われ得る（通常終了はflushで保存）。

### 3-1. アニメの Edge 残カクツキ（軽微）
Chrome/Tauri(WebView2) は滑らか。**WebView2＝Edgeエンジンが滑らかな以上、コードは十分高速**で、
Edgeブラウザの余力不足（効率モード/拡張/多タブ）が主因。さらに詰めるなら Chrome/Edge の
DevTools Performance 録画で残コスト（描画 or GC）を特定 → 必要なら描画レイヤー構成の見直し。

### 3-2. 複数/複雑Syncの時刻ズレ ✅ 対応済み（要live検証）
旧: **相手キャラ側の到達時刻が `indexOf`(最初の訪問)固定**で、同一地点を複数回通る複雑Syncでズレた。
対応: `getNodeArrivalOccurrences` を新設し、相手キャラがその地点を通る**全訪問**の到達時刻を取得。
`handleSyncTime` で「**自分の自然到達時刻に最も近い訪問**」を合流点に選ぶよう変更（最も近い訪問＝
相手の他の予定を壊しにくい）。`handleMergeConfirm` の同行範囲も選んだ訪問以降に揃えた。
単一訪問のキャラは従来と同一挙動（影響は複数訪問キャラのみ）。
→ `utils/animationUtils.ts`(新関数), `CreateView.tsx`, `modals/MergeModal.tsx`(型に `pathIndex`)。
※自分側アンカーは既にオカレンス対応済み。これで自他ともオカレンス対応。要実機検証。
