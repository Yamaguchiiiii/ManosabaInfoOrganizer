### CreateView / WaypointPanel の Sync 機能現状

```
syncConstraints: SyncConstraint[]  ← ローカル state（React）
syncTarget: { waypointId, meetingTime } | null  ← 最後のSync制約のみ保持
```

- `handleMergeConfirm` は毎回 `setSyncTarget` と `setStartTime` を更新するため、
  2回目以降のSyncで1回目の制約が破壊される
- `syncConstraints` はローカル state のため、`primaryIcon` 変更時（`useEffect`）でリセットされる
- `handleEditPath` は `syncConstraints` を復元しない

## 機能1: 複数Sync正常動作

### 問題

`handleMergeConfirm`（`CreateView.tsx:366`）は毎回 `setStartTime` を更新するため、  
2回目以降のSync実行時に1回目の制約が破壊される。

### 実装方針

**修正ファイル:** `src/components/CreateView.tsx`

1回目のSync時のみ `startTime` を調整し `syncTarget` を設定する。  
2回目以降は「自分の現在の自然到達時刻 = meetingTime」として他キャラのみ調整する。

```typescript
// handleMergeConfirm の startTime/syncTarget 更新部分を以下に差し替え
const isFirstSync = syncConstraints.length === 0;
const myAbsArrival = startTime + myCurrentTravelTime;

let meetingTime: number;

if (isFirstSync) {
    // 1回目: 全員の到達時刻の最大値が合流時刻。自分のstartTimeも調整する
    const allArrivalTimes = [myAbsArrival, ...targets.map(t => t.arrivalTime)];
    meetingTime = Math.max(...allArrivalTimes);
    const newMyStartTime = meetingTime - myCurrentTravelTime;
    setSyncTarget({ waypointId: mergeTargetWaypointId, meetingTime });
    setStartTime(newMyStartTime);
} else {
    // 2回目以降: 自分のstartTimeは固定。自分の自然到達時刻を合流時刻とする
    meetingTime = myAbsArrival;
    // syncTarget / startTime は変更しない
}
```

**`handleRemoveSyncConstraint` の修正:**

現在の実装は「最後の制約」を `syncTarget` に設定しているが、  
アンカー（startTime を支配する制約）は常に「最初の制約」であるべき。

```typescript
const handleRemoveSyncConstraint = (index: number) => {
    setSyncConstraints(prev => {
        const next = prev.filter((_, i) => i !== index);
        // アンカーは常に first constraint
        if (next.length > 0) {
            setSyncTarget({ waypointId: next[0].waypointId, meetingTime: next[0].meetingTime });
        } else {
            setSyncTarget(null);
        }
        return next;
    });
};
```

**`WaypointPanel.tsx` の `isActive` 判定修正:**

現在: `i === syncConstraints.length - 1`（最後）  
修正後: `i === 0`（最初 = アンカー）

```tsx
// WaypointPanel.tsx の syncConstraints.map 内
const isActive = i === 0; // アンカー制約をハイライト
```

また、ラベル `active` を `anchor` に変更して意味を明確化:
```tsx
{isActive && (
    <span style={{ fontSize: '0.62rem', color: '#007acc', whiteSpace: 'nowrap' }}>anchor</span>
)}
```

```typescript
const handleEditPath = () => {
    if (!savedDataRaw) return;
    const currentData = Array.isArray(savedDataRaw) 
        ? { path: savedDataRaw, waypoints: undefined, startTime: 0, syncConstraints: undefined } 
        : savedDataRaw as any;

    if (currentData.waypoints && currentData.waypoints.length > 0) {
        setWaypoints(currentData.waypoints);
    } else if (currentData.path && currentData.path.length > 0) {
        const path = currentData.path;
        const s = nodeMap[path[0]];
        const e = nodeMap[path[path.length - 1]];
        setWaypoints([
            { id: path[0], name: s?.name || "", stayTime: 0 },
            { id: path[path.length - 1], name: e?.name || "", stayTime: 0 }
        ]);
    } else {
        setWaypoints([{ id: '', name: '', stayTime: 0 }, { id: '', name: '', stayTime: 0 }]);
    }

    // syncConstraints を復元
    const restoredConstraints: SyncConstraint[] = currentData.syncConstraints || [];
    setSyncConstraints(restoredConstraints);
    if (restoredConstraints.length > 0) {
        setSyncTarget({ 
            waypointId: restoredConstraints[0].waypointId, 
            meetingTime: restoredConstraints[0].meetingTime 
        });
    } else {
        setSyncTarget(null);
    }

    setStartTime(currentData.startTime || 0);
    setIsEditing(true);
};
```

## 機能3: Add Stop 時に現在の Goal をコピー

### 問題

`handleAddWaypoint` は空の中継地点を挿入するだけで、Goalの地点情報が引き継がれない。

### 実装方針

**修正ファイル:** `src/components/CreateView.tsx`

```typescript
const handleAddWaypoint = () => {
    setWaypoints(prev => {
        const next = [...prev];
        const goal = next[next.length - 1];
        // 新しいstopにはGoalの地点をコピーし、Goalはクリアする
        const newStop: Waypoint = { id: goal.id, name: goal.name, stayTime: 0 };
        next.splice(next.length - 1, 0, newStop);
        next[next.length - 1] = { id: '', name: '', stayTime: 0 };
        return next;
    });
    setIsEditing(true);
};
```

**動作:**
- Goal が「大食堂」に設定されている → Add Stop で「大食堂」が中継地点に移動 → Goal は空
- Goal が空の場合 → Add Stop で追加された欄も空 (goal.id='' / goal.name='' がそのままコピーされるため)

## 機能5: キャラページ初期画像 `./character/` の確定と旧データ移行

### 現状

`NoteView.tsx:1812` では既に `./character/${selectedChar}` を使用している。  
ただし **既存 IndexedDB データ** に `./icon/${selectedChar}` が残っている場合、  
`charData.objects.length > 0` ガードが true となり、初期化が走らないため旧 URL が残る。

### 実装方針

**修正ファイル:** `src/components/NoteView.tsx`

キャラページ初期化の useEffect（`:1799`）に移行処理を追加する。

```typescript
useEffect(() => {
    if (activeNoteTab !== 'character') return;
    if (initializedCharsRef.current.has(selectedChar)) return;
    initializedCharsRef.current.add(selectedChar);

    const charData = useAppStore.getState().notes.characters?.[selectedChar];
    if (charData && charData.objects.length > 0) {
        // 旧データ移行: ./icon/ を使っているオブジェクトを ./character/ に更新
        const oldIconSrc = `./icon/${selectedChar}`;
        const newCharSrc = `./character/${selectedChar}`;
        charData.objects.forEach(obj => {
            if (obj.content === oldIconSrc) {
                updateNoteObject('character', selectedChar, obj.id, { content: newCharSrc }, true);
            }
        });
        return;
    }

    // 新規キャラの初期化（既存通り、./character/ を使用）
    const defaultImgSrc = `./character/${selectedChar}`;
    addNoteAsset('character', selectedChar, defaultImgSrc);
    getImageSizeFromUrl(defaultImgSrc, 800).then(size => {
        const canvasLogicalHeight = 600;
        addNoteObject('character', selectedChar, {
            id: `default_char_${Date.now()}`,
            type: 'image',
            x: 0,
            y: canvasLogicalHeight - size.height / 2,
            width: size.width, height: size.height,
            content: defaultImgSrc,
            rotation: 0, scaleX: 1, scaleY: 1,
            keepRatio: true,
            canvasIndex: 0
        });
    });
}, [selectedChar, activeNoteTab, addNoteAsset, addNoteObject, updateNoteObject]);
```

`updateNoteObject` を deps に追加するため、上部の `useAppStore` 呼び出しから取得していることを確認:
```typescript
// NoteView.tsx 内（CanvasWorkspace の外、NoteView コンポーネント内）
const addNoteAsset = useAppStore(state => state.addNoteAsset);
const addNoteObject = useAppStore(state => state.addNoteObject);
const updateNoteObject = useAppStore(state => state.updateNoteObject);  // 追加
```

## 実施上の注意

- `SyncConstraint` を `store.ts` に移動する際、`WaypointPanel.tsx` は `re-export` して
  `CreateView.tsx` の import パスを変えなくても壊れないようにする
- `saveBatchCharacterAnimations` は複数キャラに同じ `syncConstraints` を書き込むことになるが、
  バッチ保存の用途（同行キャラを一括登録）では全員同じ制約を持つので問題ない
- `any` 型禁止（CLAUDE.md）: `savedDataRaw as any` の部分は型ガードで置き換えることが望ましいが、
  既存コードで同パターンが使われているため今回はそのまま踏襲し、型改善は別タスクとする
- `computeDuration` は既に `export` 済み（store.ts）なので追加の変更不要
