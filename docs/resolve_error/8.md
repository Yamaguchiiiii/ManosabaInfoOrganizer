## 問題1: スタート・ゴールへの sync ボタン追加

### 根本原因

`WaypointPanel.tsx` では中間ウェイポイントの判定 `isIntermediate = index > 0 && index < waypoints.length - 1` を使い、⏱ ボタンを **中間ノードにのみ** 表示している。S（index=0）と G（index=waypoints.length-1）の行は `isIntermediate` が `false` のため、sync ボタンの代わりに空の `<div>` スペーサーが置かれる。

```tsx
// 現在の実装（中間のみ）
{(isIntermediate && wp.id) ? (
    <button onClick={() => handleSyncTime(wp.id, wp.name)} ...>⏱</button>
) : (
    <div style={{ width: '24px' }} />
)}
```

S・G に対応するノードが地図上で確定している場合（`wp.id` がある場合）は sync が可能なはずだが、`isIntermediate` 条件で完全に除外されている。

### 修正対象ファイル

- `src/components/create/WaypointPanel.tsx`

### 修正内容

`isIntermediate` 条件を外し、`wp.id` が存在する場合は常に sync ボタンを表示するよう変更する。

```tsx
// 変更前
{(isIntermediate && wp.id) ? (
    <button onClick={() => handleSyncTime(wp.id, wp.name)} title="Sync"
        style={{ background: '#333', border: '1px solid #555', color: '#fbbf24', width: '24px', height: '24px', borderRadius: '4px', cursor: 'pointer', display: 'flex', alignItems: 'center', justifyContent: 'center', fontSize: '0.9rem' }}
    >⏱</button>
) : (
    <div style={{ width: '24px' }} />
)}

// 変更後
{wp.id ? (
    <button onClick={() => handleSyncTime(wp.id, wp.name)} title="Sync"
        style={{ background: '#333', border: '1px solid #555', color: '#fbbf24', width: '24px', height: '24px', borderRadius: '4px', cursor: 'pointer', display: 'flex', alignItems: 'center', justifyContent: 'center', fontSize: '0.9rem' }}
    >⏱</button>
) : (
    <div style={{ width: '24px' }} />
)}
```

## 問題2: グループ化テキストオブジェクトがドラッグ時に移動しない

### 根本原因

Konva は `draggable` を持つノードを**個別に**独立ドラッグする。グループ化されているオブジェクト A をドラッグすると、Konva は A の Konva ノードのみを物理的に移動する。同じ `groupId` を持つテキストノード T はドラッグの対象外であり、ドラッグ中も `onDragEnd` 後も座標が変わらない。

現在の `onDragEnd` は:

```typescript
// ShapeObject / EditableText 両方の現実装
onDragEnd: (e) => onChange({ x: e.target.x(), y: e.target.y() })
// onChange: updateNoteObject(obj.id だけ更新)
```

グループ全員を一括移動する仕組みが存在しない。ドラッグ中の visual 移動（`onDragMove`）も同様に他メンバーへの伝播がないため、テキストはドラッグが終わるまで元の位置に留まる。

### 修正対象ファイル

- `src/components/NoteView.tsx`

### 修正内容

`props` の `onDragMove` と `onDragEnd` オーバーライドで、グループメンバーを追従させる。

**① props にグループ用ハンドラを追加**（Layer 内のオブジェクトレンダリングブロック）

```typescript
const groupDragHandlers = obj.groupId ? {
    onDragMove: (e: any) => {
        const dx = e.target.x() - (obj.x ?? 0);
        const dy = e.target.y() - (obj.y ?? 0);
        const stage = trRefs.current[index]?.getStage();
        currentCanvasObjects
            .filter(o => o.groupId === obj.groupId && o.id !== obj.id)
            .forEach(member => {
                const node = stage?.findOne(`#${member.id}`);
                if (node) {
                    node.x((member.x ?? 0) + dx);
                    node.y((member.y ?? 0) + dy);
                }
            });
        trRefs.current[index]?.getLayer()?.batchDraw();
    },
    onDragEnd: (e: any) => {
        const dx = e.target.x() - (obj.x ?? 0);
        const dy = e.target.y() - (obj.y ?? 0);
        const groupObjs = currentCanvasObjects.filter(o => o.groupId === obj.groupId);
        saveHistoryOnceThenSkip();
        updateNoteObjects(targetType, displayTargetId,
            groupObjs.map(m => ({ id: m.id, attrs: { x: (m.x ?? 0) + dx, y: (m.y ?? 0) + dy } }))
        );
    },
} : {};

const props = {
    ...,
    onChange: (newAttrs: NoteObject) => {
        saveHistoryOnceThenSkip();
        updateNoteObject(targetType, displayTargetId, obj.id, newAttrs, true);
    },
    ...groupDragHandlers,
    ...
};
```

**② EditableText に `onDragMove` / `onDragEnd` prop を追加**

```tsx
const EditableText = React.memo(({ textObj, onSelect, onChange, onToggleEdit, onDragMove, onDragEnd, isDrawingMode }: any) => {
    return (
        <Text
            ...
            onDragMove={onDragMove}
            onDragEnd={onDragEnd ?? ((e: any) => onChange({ x: e.target.x(), y: e.target.y() }))}
        />
    );
});
```

**③ ShapeObject に `onDragMove` / `onDragEnd` prop を追加**

```typescript
const ShapeObject = React.memo(({ shapeObj, onSelect, onChange, onContextMenu, onDragMove, onDragEnd, isDrawingMode }: any) => {
    const commonProps: any = {
        ...
        onDragMove: onDragMove,
        onDragEnd: onDragEnd ?? ((e: any) => onChange({ x: e.target.x(), y: e.target.y() })),
        ...
    };
```

`onDragMove` の計算は **ドラッグ前のストア座標** (`obj.x`, `obj.y`) を基準に delta を計算するため、ドラッグ中にストアが更新されないこと（`skipHistory=true` かつ `onDragMove` では更新しない）が前提。この前提は現在の実装で満たされている。

## 問題3・4: キャンバス論理座標系の不統一（ズーム問題と兼用）

### 根本原因（問題3・問題4共通）

**問題3（キャンバスサイズ不一致）:**

`NoteView.tsx` の `CanvasWorkspace` は `compactMode` によって2種類のスケール計算を使用する:

| モード | スケール計算 | 論理座標系 |
|--------|------------|----------|
| `compactMode = true`（NotesPanel） | `scale = min(w/1200, h/800)` | 固定 1200×800 |
| `compactMode = false`（NoteView）  | `scale = 1`（無変換）        | コンテナサイズに依存 |

NoteView のプリセットキャンバスが 900×600 のコンテナで表示されている場合、論理座標系は 900×600。NotesPanel は常に 1200×800 を論理サイズとして解釈するため、同じ `(x, y)` データが異なる相対位置に表示される。

**問題4（ズームでサイズ変化）:**

ブラウザのズームインは CSS ピクセルサイズを縮小する。`ResizeObserver` は CSS ピクセル単位の `contentRect.width/height` を返すため、ズームすると報告サイズが変化する。`compactMode = false` で `scale = 1` の場合、Stage の width/height がコンテナサイズに直接バインドされるため、ズームによってキャンバスが縮小・拡大する。

### 修正対象ファイル

- `src/components/NoteView.tsx`

### 修正内容

**両問題の根本解決**: 非 compact モードでも固定論理サイズ（1200×800）を使用し、`scale` をコンテナに合わせて計算する。

```typescript
// 変更前
const COMPACT_BASE_WIDTH = 1200;
const COMPACT_BASE_HEIGHT = 800;

let scale = 1;
if (compactMode) {
    scale = Math.min(stageWidth / COMPACT_BASE_WIDTH, stageHeight / COMPACT_BASE_HEIGHT);
} else if (isGridMode) {
    scale = 0.5;
}

// 変更後
const CANVAS_BASE_WIDTH = 1200;
const CANVAS_BASE_HEIGHT = 800;

let scale: number;
if (isGridMode) {
    scale = 0.5;
} else {
    // compact/非compact 共通: コンテナに収まるよう縮小、最大1.0
    scale = Math.min(stageWidth / CANVAS_BASE_WIDTH, stageHeight / CANVAS_BASE_HEIGHT, 1);
}
```

`scale = Math.min(..., 1)` の上限 1 を設けることで、コンテナが論理サイズより大きい場合は 1:1 表示（拡大しない）になる。必要に応じて上限を外し、コンテナ全体にフィットさせることも可能。

> **注意:** 非 compact モードでは従来 `scale = 1` だったため、既存データの座標はコンテナ CSS ピクセル単位で記録されている。この変更後は論理座標系が 1200×800 に固定されるため、既存オブジェクトの見た目上の位置が変化する可能性がある。新規作成ページでは問題ない。既存データの移行が必要な場合は、変更前のコンテナサイズを記録し変換する追加処理が必要だが、現実装ではコンテナサイズを永続化していないため困難。実際的な対処として「修正以降のデータは新座標系で記録される」として運用するか、ユーザーに通知する。

## 問題5: 透明背景画像の自動クロップ

### 根本原因

`processFile()` は `FileReader` で画像を読み込み、`<img>` 要素のサイズから `width/height` を決定する。この際、画像全体のサイズ（透明ピクセルを含む）を返す。PNG の透明背景部分も含めてバウンディングボックスが設定されるため、実際の前景（キャラクター等）より大きい空白領域がキャンバス上に占有される。

### 修正対象ファイル

- `src/components/NoteView.tsx`

### 修正内容

`processFile()` の内部に Canvas API によるアルファチャンネル解析・クロップ処理を追加する。

```typescript
const autocropTransparent = (
    originalBase64: string,
    imgWidth: number,
    imgHeight: number
): Promise<{ base64: string; width: number; height: number }> => {
    return new Promise((resolve) => {
        const canvas = document.createElement('canvas');
        canvas.width = imgWidth;
        canvas.height = imgHeight;
        const ctx = canvas.getContext('2d');
        if (!ctx) { resolve({ base64: originalBase64, width: imgWidth, height: imgHeight }); return; }

        const img = new Image();
        img.onload = () => {
            ctx.drawImage(img, 0, 0);
            const data = ctx.getImageData(0, 0, imgWidth, imgHeight).data;
            const ALPHA_THRESHOLD = 10;

            let minX = imgWidth, minY = imgHeight, maxX = 0, maxY = 0;
            for (let y = 0; y < imgHeight; y++) {
                for (let x = 0; x < imgWidth; x++) {
                    if (data[(y * imgWidth + x) * 4 + 3] > ALPHA_THRESHOLD) {
                        minX = Math.min(minX, x);
                        minY = Math.min(minY, y);
                        maxX = Math.max(maxX, x);
                        maxY = Math.max(maxY, y);
                    }
                }
            }

            // 全透明の場合はクロップしない
            if (maxX < minX || maxY < minY) {
                resolve({ base64: originalBase64, width: imgWidth, height: imgHeight });
                return;
            }

            const cropW = maxX - minX + 1;
            const cropH = maxY - minY + 1;
            const cropCanvas = document.createElement('canvas');
            cropCanvas.width = cropW;
            cropCanvas.height = cropH;
            const cropCtx = cropCanvas.getContext('2d')!;
            cropCtx.drawImage(canvas, minX, minY, cropW, cropH, 0, 0, cropW, cropH);

            // maxDimension スケーリング
            let w = cropW, h = cropH;
            const maxDim = 500;
            if (w > h) { if (w > maxDim) { h = Math.round(h * maxDim / w); w = maxDim; } }
            else       { if (h > maxDim) { w = Math.round(w * maxDim / h); h = maxDim; } }

            resolve({ base64: cropCanvas.toDataURL('image/png'), width: w, height: h });
        };
        img.src = originalBase64;
    });
};
```

`processFile()` 内でこの関数を呼び出す:

```typescript
const processFile = (file: File): Promise<{ base64: string, width: number, height: number }> => {
    return new Promise((resolve, reject) => {
        const reader = new FileReader();
        reader.onload = async (e) => {
            const base64 = e.target?.result as string;
            const img = new Image();
            img.onload = async () => {
                const cropped = await autocropTransparent(base64, img.width, img.height);
                resolve(cropped);
            };
            img.onerror = reject;
            img.src = base64;
        };
        reader.onerror = reject;
        reader.readAsDataURL(file);
    });
};
```

これにより `addNoteAsset` に保存される base64 が「クロップ済み画像」になる。クロップ後の画像が asset として保存されるため、再度読み込んだ時も同じサイズが維持される。

> **注意:** `getImageData` はクロスオリジンのリソースには使えないが、`processFile` は `FileReader` でローカルファイルを base64 変換したデータを扱うため、クロスオリジン制限は発生しない。

## 問題6: 画像のアスペクト比ロック（デフォルト ON + トグル UI）

### 根本原因

1. `NoteObject` インターフェースに `keepRatio` フィールドが存在しない
2. `Transformer` の `keepRatio` prop はオブジェクトの種別・設定に関わらず、`circle`/`triangle` の場合のみ `true` に固定されている
3. 画像が選択された時に `keepRatio` を切り替えるための UI が存在しない

結果として、画像オブジェクトは `keepRatio=false` で自由に変形でき、アスペクト比が壊れやすい。

### 修正対象ファイル

- `src/store.ts`
- `src/components/NoteView.tsx`

### 修正内容

**① `store.ts`: `NoteObject` に `keepRatio` フィールドを追加**

```typescript

    id: string; type: NoteObjectType; x: number; y: number; width?: number; height?: number;
    rotation?: number; scaleX?: number; scaleY?: number; fill?: string; text?: string;
    fontSize?: number; fontWeight?: string; content?: string; stroke?: string;
    strokeWidth?: number; points?: number[]; lineStyle?: 'normal' | 'marker' | 'pen';
    canvasIndex?: number; groupId?: string;
```

**② `NoteView.tsx`: 画像追加時にデフォルトで `keepRatio: true` を設定**

`handleDrop`、`handleStageMouseUp`（isDrag/クリック両方）、`addNoteObject('image', ...)` を呼ぶすべての箇所に `keepRatio: true` を追加する:

**③ `NoteView.tsx`: Transformer の `keepRatio` を `NoteObject.keepRatio` から取得**
