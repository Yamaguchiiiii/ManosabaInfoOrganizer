## ✅ 実装済み

### #1 ノート種別ごとのCanvas表示方式（`NoteView.tsx`）
`useRangeFit = (targetType === 'preset')` を導入。
- preset(事件ノート): 基準範囲 1200×800(3:2) フィット（中央レターボックス、Animateと整合）。**現状維持**。
- overview/character/misc: Stageをコンテナ実寸にして**要素いっぱいに描画(fill)**。ズームではサイズ変更しないが余白も出ない。
- 配置/ドラッグの範囲クランプ `[0,1200]×[0,800]` は preset のみ適用。fill側は自由配置。

### #2 Character Images / Empty 表示
- Images = ユーザー追加画像(assets)。preset では立ち絵も併載（従来通り）。`portraitPalette` と `assets` がともに空なら **"Empty"** を表示。
- preset以外は Images の下に **Character Images** 見出しを追加し、全キャラの立ち絵(`CHARACTER_PORTRAITS`)を常時表示（クリックで配置）。
- ToolsのImageから追加した画像は従来通り Images(assets) に入る。

### #3/#4/#5 トップバー廃止 → Tools上に集約

- #4 misc: 「Misc Notes」トップバーを廃止し、ページ選択/追加(+)/改名/削除を sidebarHeader へ（メモ未作成時は中央に Create ボタン）。

### #6 ズームイン時の画質劣化（`NoteView.tsx`）
原因: Konva は各 Layer canvas の `pixelRatio` をマウント時の `devicePixelRatio` で固定する。ブラウザのズームインで dpr が上がっても再描画されず、拡大表示でバックバッファ解像度が不足してボケる（再読み込みで直るのはその時点の dpr で描き直すため）。
修正: `(resolution: Xdppx)` メディアクエリで dpr 変化を検知し、各 Stage の Layer canvas に `setPixelRatio(dpr)` を再適用して `batchDraw()`。`stageRefs` を追加。

### #9 Space で再生/停止（`AnimateView.tsx`）
`keydown` で Space を捕捉し `usePlaybackStore.setIsPlaying(!isPlaying)`。入力欄(input/textarea/select/contentEditable)フォーカス中は無効。

### #10 "Day" → "Episode"（`store.ts`）
`addPreset` の `name: \`Day ${num}\`` を `Episode ${num}` に。

### #11 画像一覧ギャラリーのドラッグ移動（`NoteView.tsx`）

## ✅ #7 Createページの4ペイン化＋右下広告

### 設計判断（activeFloor を見直すか）
監査の結果、`activeFloor` は **CreateView（描画＋編集対象）と Sidebar（フロアボタン強調）でのみ**使用され、Animate/Note は未使用。ストア/persist を変える価値は薄い。問題の本質は `activeFloor` が**編集に対して load-bearing**（新規ノード/エッジが大域状態を読む）な点。
→ **ストアの再設計はしない。** 代わりに**編集対象フロアをペイン単位で明示**する設計に変更:
- `FloorPane` コンポーネントを新設。各ペインが自前の Stage / ズーム / 計測を持ち、`floorId` を編集ハンドラ（addNode/addEdge）に**明示的に渡す**ため編集対象が曖昧でない。
- `activeFloor` は**ホバー駆動のUIヒント**（アクティブペインの枠・サイドバー強調）に格下げ。ペインの `mouseenter` で `setActiveFloor`。都度選択は不要でUXを損なわない。
- 副次効果: フロアをまたいでノードをクリックして**複数フロアにまたがる経路を直接構築**できるようになった（従来はフロア切替が必要）。
- `handleStageClick`/`handleNodeClick` は `floorOverride`（省略時 `activeFloor`）を受ける後方互換シグネチャ。
- 単一Stage用の大域 `stageRef/containerRef/size/getMapSrc/useStageZoom` を撤去。

## ⏳ 未実装（方針）

### #8 レスポンシブな 2x2 / 4x1 切替（#7完了済→次対応可）
- **方針**: コンテナ実寸 (W×H) とマップ画像のアスペクト比 a=mapW/mapH から、各配置でのマップ表示倍率 `scale=min(cw/mapW, ch/mapH)` を比較し、**マップが最大になる配置**を選ぶ。
  - 2x2: セル = W/2 × H/2
  - 1x4(縦積み): セル = W × H/4 → 横長マップ＋縦長ウィンドウ(win+left)で有利
  - 4x1(横並び): セル = W/4 × H → 横長ウィンドウで不利になりがち
- `ResizeObserver` でコンテナを測り、`grid-template-columns/rows` を切替（AnimateView/CreateView 共通のフックに切り出す想定）。Animate は4セル目が操作セルのため、マップ3セルの倍率最大化を基準にする。
- Create の4ペイン(#7)が前提のため、#7 実装後にまとめて対応する。
