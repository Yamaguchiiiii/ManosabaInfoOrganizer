### #6 ズームイン時の画質劣化（`NoteView.tsx`）
原因: Konva は各 Layer canvas の `pixelRatio` をマウント時の `devicePixelRatio` で固定する。ブラウザのズームインで dpr が上がっても再描画されず、拡大表示でバックバッファ解像度が不足してボケる（再読み込みで直るのはその時点の dpr で描き直すため）。
修正: `(resolution: Xdppx)` メディアクエリで dpr 変化を検知し、各 Stage の Layer canvas に `setPixelRatio(dpr)` を再適用して `batchDraw()`。`stageRefs` を追加。

### #7 Createページの4ペイン化＋右下広告（相談）
- **方針**: Animate と同じ 2x2 配置（Map1=2F / Map2=1F / Map3=B1 / 右下=空き）で全フロアを同時表示する。ただし Create は「1フロアを編集する」インタラクション（フロア切替・経路描画・ノード追加）が前提のため、**「どのペイン(フロア)が編集対象か」**の設計が必要（例: クリックした／枠で示したペインをアクティブ編集フロアにし、他ペインは読み取り専用プレビュー）。現状の `activeFloor` 切替UIをペイン選択に置き換える形になり、影響範囲が大きいので独立対応とする。
- **広告について（回答）**: 技術的には右下ペインに広告枠を置くことは可能です。ただし注意点があります:
  1. **Web版**: Google AdSense 等は `<script>`/`<ins>` を埋め込めば表示可能。ただしSPA(React)では「広告が表示に足る独自コンテンツのあるページ」等のポリシー審査があり、ツール系UIの一画面に貼ると不承認・制限のリスク。`<iframe>` 型の広告ネットワークなら比較的容易。
  2. **デスクトップ版(Tauri/WebView2)**: ローカルオリジンで動くため、多くの広告ネットワークの規約(対象は公開Webサイト)や計測スクリプトのオリジン制約に抵触しやすく、AdSense は実質不可。Tauri 向けには広告SDKがないため、自前のハウス広告(画像＋リンクを `shell.open` で外部ブラウザ起動)が現実的。
  3. **推奨**: まず右下ペインを「ハウス広告/お知らせ枠(画像＋外部リンク)」として実装し、Web版のみ条件付きで広告ネットワークを差し込むアダプタ構成（`src/services` で web/desktop 分岐）にするのが、クロスプラットフォーム規約(CLAUDE.md)に沿って安全。
- 実装可否・方針（ハウス広告か広告ネットワークか）をご確認のうえ着手予定。

### #8 レスポンシブな 2x2 / 4x1 切替（#7依存）
- **方針**: コンテナ実寸 (W×H) とマップ画像のアスペクト比 a=mapW/mapH から、各配置でのマップ表示倍率 `scale=min(cw/mapW, ch/mapH)` を比較し、**マップが最大になる配置**を選ぶ。
  - 2x2: セル = W/2 × H/2
  - 1x4(縦積み): セル = W × H/4 → 横長マップ＋縦長ウィンドウ(win+left)で有利
  - 4x1(横並び): セル = W/4 × H → 横長ウィンドウで不利になりがち
- `ResizeObserver` でコンテナを測り、`grid-template-columns/rows` を切替（AnimateView/CreateView 共通のフックに切り出す想定）。Animate は4セル目が操作セルのため、マップ3セルの倍率最大化を基準にする。
- Create の4ペイン(#7)が前提のため、#7 実装後にまとめて対応する。
