## #6 カラーピッカーの激重＋OOM ✅
原因は2つ:
1. **OOM**: `updateNoteObject` が `useAppStore.setState`→persist で巨大stateを毎回 IndexedDB に書く
   （= 3-1b と同根）。→ store の persist debounce（commit `2285431`）で解消済み。
2. **激重**: カラーピッカーの `onChange` が連続発火し、毎回 `setShapeContextMenu`＋`updateNoteObject`
   →キャンバス全再描画（オブジェクトのコールバックが毎レンダ再生成でmemo無効）。
   → 連続入力のコミットを間引く `commitThrottled`（先頭即時＋末尾100ms）を新設し、
   Line Color / Line Width / Fill Color に適用（`NoteView.tsx`）。ネイティブpiピッカーの
   ダイアログは即時、ページ側の反映のみ間引き。

## #3 ズームでCanvasサイズが変わる ✅（ブラウザ Ctrl+/−）
原因: 単一表示の `scale=min(stageW/1200, stageH/800, 1)` の **上限1** により、低ズームでは 1:1（余白あり）、
ズームインでコンテナのCSSピクセルが 1200×800 を下回ると scale が下がり**非対称に縮小**していた。
修正: **上限1を撤去**し常にコンテナへフィット（`scale=min(stageW/1200, stageH/800)`）。
コンテナは width/height 100%＝物理サイズ一定のため、ブラウザズームで内部のCSSピクセルが変わっても
キャンバスはコンテナを埋め続け、**見かけ(物理)サイズが一定**になる。論理座標系(1200×800)は不変。
※副作用: 大画面の100%表示でキャンバスが余白なくフィットする（1:1固定ではなくなる）。

追記（4ペイン）: **グリッド表示は固定 `scale=0.5`** だったため、これもCSSピクセル基準でズーム非対応だった。
単一/グリッドとも同じ「ステージ(=セル)いっぱいにフィット」式に**統一**（`stageW/H` は単一=コンテナ、
グリッド=各セルの実寸）。これで4ペイン表示でもズームで見かけサイズが変わらず、各セルにぴったり収まる。
