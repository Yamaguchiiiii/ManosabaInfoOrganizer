# resolve_error/9.md — Sync 複雑操作時のタイミングズレ + Sync UI 改善

対象症状: `docs/_symptoms.md #05/20_19:00` 問題1・問題2

---

## 問題の整理

### 問題1: 複雑なSync操作でタイミングがずれる

AがBと同行後 C に出会い、C を D に引き渡す…などの多段 Sync を行うと、
同行・すれ違い等の地点タイミングがずれる。

### 問題2: 複雑な使い方に Sync UI が対応できない

現在の UI では：
- Sync制約が複数になっても一切表示されない（「今何個Syncしたか」がわからない）
- どの地点で誰とSyncしたか確認・取り消しができない
- 複数Syncの整合性をユーザーが視覚的に確認できない

---

## 根本原因の分析

### 原因A（問題1・最重要）: `handleSyncTime` の `duration` 計算が実際と異なる

`CreateView.tsx` の `handleSyncTime`（行323〜361）内：

```typescript
const tempData = {
    path: displayPath,
    startTime: 0,
    duration: Math.max(displayPath.length * 30, 60),  // ← ノード数×30 の近似値
    waypoints
};
const myTime = calculateNodeArrivalTime(tempData, waypointId, nodes);
```

一方、実際に `saveCharacterAnimation` でストアに保存される `duration` は `store.ts` の
`computeDuration()` 関数が計算する「ピクセル距離 ÷ 移動速度（px/s ÷ TARGET_FPS）」。

`calculateNodeArrivalTime` は `startTime + duration * (distToTarget / totalDist)` を返すため、
`duration` の値が保存値と食い違うと、「Sync時に計算した myTime」と「実際のアニメーションの
到達フレーム」がずれ、MergeModal で選択した相手との meetingTime がずれたまま保存される。

また `syncTarget` useEffect（行182〜202）でも同じ仮値を使っており、パス変更のたびに
誤った `startTime` が再セットされ、ずれが蓄積する：

```typescript
const tempData = {
    path: displayPath,
    startTime: 0,
    duration: Math.max(displayPath.length * 30, 60),  // ← ここも同じ問題
    waypoints
};
```

### 原因B（問題1）: 2回目以降の Sync で最初の Sync 制約が消える

`syncTarget` state は単一のオブジェクト（`{ waypointId, meetingTime } | null`）のみ保持する。
2回目の Sync 操作で `setSyncTarget({ ... })` が呼ばれると1回目の制約が上書きされ、以降の
パス変更時に1回目の Sync 地点でのタイミングが維持されなくなる。

複数地点でSyncした場合の整合性が保証されない。

### 原因C（問題2）: Sync 制約が UI に一切表示されない

`syncTarget` は state として存在するが、`WaypointPanel` に渡されておらず描画されない。
Sync をいくつかけたか・どの地点か・誰との同期か、ユーザーには全く見えない。

## 修正方針

### 修正1: `computeDuration` を export に変更（`store.ts`）

現在 `const computeDuration` はファイル内 private で定義されている。
`CreateView.tsx` でも同じ計算を使えるよう export する。

```typescript
// store.ts — "const computeDuration" を "export const computeDuration" に変更するだけ
export const computeDuration = (path: string[], nodes: MapNode[]): number => {
    const nodesMap: Record<string, MapNode> = {};
    nodes.forEach(n => { nodesMap[n.id] = n; });
    let totalDist = 0;
    for (let i = 0; i < path.length - 1; i++) {
        const nA = nodesMap[path[i]];
        const nB = nodesMap[path[i + 1]];
        if (!nA || !nB) continue;
        if (nA.id === nB.id) { totalDist += WAIT_VIRTUAL_DISTANCE; continue; }
        if ((nA.type === 'stair' && nB.type === 'stair') || nA.floor !== nB.floor) continue;
        totalDist += Math.sqrt((nB.x - nA.x) ** 2 + (nB.y - nA.y) ** 2);
    }
    return Math.max(totalDist / (MOVEMENT_SPEED_PX_PER_SEC / TARGET_FPS), 60);
};
```

```typescript

// 追加: 制約をリストに蓄積（同一地点の重複はUpsert）
setSyncConstraints(prev => {
    const existingIdx = prev.findIndex(c => c.waypointId === mergeTargetWaypointId);
    const newConstraint: SyncConstraint = {

        waypointName: mergeTargetWaypointName,

        next[existingIdx] = newConstraint;
        return next;
```


**制約の削除ハンドラ:**

```typescript
const handleRemoveSyncConstraint = (index: number) => {
    setSyncConstraints(prev => {
        const next = prev.filter((_, i) => i !== index);
        // 削除された制約が最後（= active）だった場合は syncTarget もリセット
        if (index === prev.length - 1) {
            if (next.length > 0) {
                const last = next[next.length - 1];
                setSyncTarget({ waypointId: last.waypointId, meetingTime: last.meetingTime });
            } else {
                setSyncTarget(null);
            }
        }
        return next;
    });
};
```

## 実装上の注意点

- `SyncConstraint` 型は `CreateView.tsx` 内での定義で十分（`WaypointPanel` は inline で参照 or export）。`store.ts` には追加不要（保存する必要がない一時的な編集状態）。
- `computeDuration` は `store.ts` と `CreateView.tsx` で同じ実装を維持するため、export しておく方が DRY。
- `handleSavePath` 時は `syncConstraints` をリセットしない（保存後も確認できるようにする）。ただし次のキャラ選択時にはリセットする。
- `any` 型を使わないこと（CLAUDE.md）。`CharacterTimelineData` を明示的に使う。
- `WaypointPanel` の `maxWidth: '300px'` を超えないよう、Sync Constraints の各行は1行に収める（テキストオーバーフローは `ellipsis` で処理）。
