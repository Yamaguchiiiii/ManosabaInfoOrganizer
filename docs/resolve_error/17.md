## #1 跨ぎドラッグの座標がおかしい（`NoteView.tsx handleObjectDragEnd`）
### 原因
事件ノート(preset)の範囲クランプ `[0,1200]×[0,800]` を、跨ぎ移動の計算より**前に**ソース座標
`localX = clamp(e.target.x())` へ適用していた。隣のペインへドラッグすると `e.target.x()` はソース範囲外
（例: 右隣へ → 1200超）になり、クランプで 1200 等に丸められてから跨ぎオフセットを足すため、
移動先の**端へ飛ぶ／ドロップ位置とずれる**（症状の「たまにペインの端に配置」と一致）。

### 修正
1. ドラッグ後の**生の論理座標 `rawX/rawY`（クランプ前）**で計算する。
2. 跨ぎ移動は **Stage コンテナの画面矩形 + Layer の scale/offset** を使い、ドロップされたオブジェクト原点の
   画面座標 → 移動先 Layer の論理座標へ正確に変換（ペインのレターボックス中央寄せやツールバー帯にも追従）。
   ```
   screenX = srcBox.left + rawX * sLayer.scaleX() + sLayer.x()
   newX    = (screenX - tgtBox.left - tLayer.x()) / tLayer.scaleX()
   ```
3. クランプは**最終座標 `newX/newY` に対してのみ**適用。
4. 移動対象セットはソースペインのオブジェクトに限定（別ペインのドラッグでも正しく対象を取得）。

## #2 4ペイン編集での跨ぎ shift 選択ができない（`NoteView.tsx`）

### 原因（徹底分析の結果＝真因）
当初 (1) onSelect が shift 時に current ペインを移さない、(2) Transformer を全ペインに描画、の2点を直したが
**まだ機能しなかった**。真因は **Stage の `onMouseDown` ラッパー**だった:
```
onMouseDown={(e) => {
  ...
  if (isGridMode && isGridEditMode && !isCurrent) {   // ← shift を考慮していない
    setCurrentCanvasIndex(index);
    setSelectedIds([]);                                // ← ここで選択を全消し
  }
  handleStageMouseDown(...);
}}
```
イベント順序は **mousedown → click**。別ペインのオブジェクトを shift+クリックすると、まず Stage の `onMouseDown`
が発火して `setSelectedIds([])` で**直前までの選択（ペインAの分）を消去**し、そのあとに発火する
オブジェクトの `onSelect`(click) が新しい1個だけを追加していた。結果、常に最後の1個しか残らず「跨ぎ選択できない」。
（青枠＝current ペインの強調が動くのも、この `setCurrentCanvasIndex` のため。ユーザーの見立て通り。）

### 修正→撤回（`3c287c6`）
shift 時に current 切替/選択クリアを抑止＋全ペイン Transformer 描画で対応したが、**4ペイン選択全体の挙動が
おかしくなった**ためユーザー要望で撤回し、元の選択挙動に戻した（onSelect は current ペイン基準、非current の
mousedown で切替＋クリア、Transformer は current のみ、同一ペインの shift トグルは従来どおり）。
※ #4(テキスト編集の性能) と #1(跨ぎドラッグの座標修正) は維持。

### 再設計メモ（次回・要 live 検証）
跨ぎ複数選択は、per-Stage の click/mousedown/Transformer が「current ペイン」前提に密結合しているのが根因。
小手先のガードでは別ペインの mousedown→click 順序や Transformer 可視範囲と競合する。安全にやるなら、
**4ペイン編集を単一 Stage（1つの Konva Stage に全ペインをサブグループ配置）へ作り替える**等、選択/変形の
基盤設計から見直すのが望ましい（影響大のため独立タスク）。
