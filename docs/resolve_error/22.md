## §A 【症状1】パネル折りたたみで Canvas にグレー空白 — レターボックス方式を「fill × 縮尺安定」方式へ変更

### 経緯と原因（推測ではなく実装済みコードの仕様）

21.md §A で「パネル開閉で見える範囲が変わる」(0711 #1) を直すため、**論理ビューポートをウィンドウ基準の安定寸(`stableSize`)に固定し、実セルとの差はレターボックス（等倍縮小＋暗色マージン）で吸収する**方式を実装した。

- `src/components/note/CanvasWorkspace.tsx` L153-157（grep: `const [stableSize, setStableSize]`）: 安定寸 state。
- 同 L236-254（grep: `return prev;    // ウィンドウ不変のコンテナ変化`）: ResizeObserver 内で、ウィンドウ寸が変わらない限り stableSize を据え置く。
- 同 L1218-1235（grep: `const useStable = !compactMode && stableSize.width > 0;`）: 安定寸から論理ビューポート(viewW/viewH)を出し、`effScale = min(stageWidth/viewW, stageHeight/viewH)` で実セルへ**アスペクト維持フィット** → セルとビューポートの縦横比が違うと `stageOffsetX/Y` 分の暗色マージン（ペイン背景 `#1e1e1e`）が出る。

つまり今回の「グレー空白」は 21§A の**意図した**レターボックスそのもの。ContextPanel（App.tsx L161 `{!contextPanelCollapsed && <ContextPanel />}`、ContextBar の「▶」/パネルの「◀」で開閉）を折りたたむとコンテナが横に広がり、縦横比が安定寸とズレるため左右…実際には縦横比次第で上下にもグレー帯が出る。4ペインでも各セルが同じ比率計算をするので**4面全部に同じグレーが出る**（症状の後半と一致）。

### 方針決定

要求は「(a) パネル開閉で見えていた内容が隠れたり出たりしない（0711 #1）」かつ「(b) グレー余白を出さない（今回）」。固定アスペクトのレターボックスでは (b) を満たせない。両立する幾何は1つ:

**「fill × 縮尺安定」方式 — 縮尺(effScale)は stableSize（ウィンドウ基準）だけから決めて固定し、紙面(Stage)は常にセルいっぱいに描く。**

- パネル開閉ではズームも移動も起きない（縮尺不変・方眼ピッチ不変）。
- セルが広がった分は**紙面がそのまま広がる**（新しい余白紙面が右/下に現れる）→ グレーなし。
- セルが狭まった分は**紙面の右/下端がパネルの下に隠れる**（机に固定した紙の上をパネルが滑るイメージ）。隠れた領域のオブジェクトは既存の「🧲 画面外を回収」で戻せる。
- ウィンドウ自体のリサイズ時は従来どおり stableSize が更新され、紙面全体が再フィット（ズーム）する。
- `stableSize == 実寸` のとき旧 fill と完全一致（compact も従来どおり fill のまま不変）。
- **事件ノート(preset) は対象外**: 1200×800 固定＋レターボックスは Animate との整合のための仕様なので従来どおり（preset のグレー余白は残る。気になる場合の色調整は refactoring3.md B-15 参照）。

## §E 【症状5】PNG 書き出しに点線グリッド背景を含める

### 現状

- 紙面の方眼は Stage の **CSS 背景**（`CanvasWorkspace.tsx` grep: `backgroundImage: 'url("data:image/svg+xml`、24pxピッチ・`#C2B2A1`・3-3破線・各セルの上辺と左辺）なので `stage.toDataURL` に写らない。
- `handleExportPng`（grep: `const handleExportPng`）は合成時に紙面色 `#ECD2B3` の**塗りのみ**行っている（単ペイン L356、4ペイン L372）。

書き出しスケールの前提: `capturePane` は `pixelRatio: 2 / s`（s = Layer scale）で出力するため、**出力pxは常に「論理px × 2」**（ウィンドウ寸非依存）。したがって方眼は出力上 48px ピッチ・破線 6px・線幅 2px で描けば画面と相似になる。

### 実装（`CanvasWorkspace.tsx`）

**1. ヘルパー追加** — `loadImage`（grep: `const loadImage = (url: string)`）の直後:
```tsx
// 0711_2 #5: 紙面（方眼つき）を 2D canvas に描く。k = 出力px/論理px。
// capturePane の pixelRatio(2/s) と Layer scale(s) が相殺するため、書き出しは常に k=2。
// 見た目は画面の CSS 背景（24pxピッチ・3-3破線・#C2B2A1・各セルの上辺/左辺）に一致させる。
const drawPaper = (ctx: CanvasRenderingContext2D, w: number, h: number, k: number) => {
    ctx.fillStyle = '#ECD2B3';
    ctx.fillRect(0, 0, w, h);
    ctx.strokeStyle = '#C2B2A1';
    ctx.lineWidth = k;
    ctx.setLineDash([3 * k, 3 * k]);
    for (let x = 0; x <= w; x += 24 * k) {
        ctx.beginPath(); ctx.moveTo(x, 0); ctx.lineTo(x, h); ctx.stroke();
    }
    for (let y = 0; y <= h; y += 24 * k) {
        ctx.beginPath(); ctx.moveTo(0, y); ctx.lineTo(w, y); ctx.stroke();
    }
    ctx.setLineDash([]);
};
```

**2. 単ペイン書き出し**（grep: `ctx.fillStyle = '#ECD2B3'; ctx.fillRect(0, 0, c.width, c.height);`）を置換:
```tsx
drawPaper(ctx, c.width, c.height, 2);
ctx.drawImage(img, 0, 0);
```

**3. 4ペイン書き出し** — ループ内（grep: `ctx.fillStyle = '#ECD2B3'; ctx.fillRect(x, y, w, h);`）を置換:
```tsx
ctx.save();
ctx.translate(x, y);
drawPaper(ctx, w, h, 2);
ctx.restore();
ctx.drawImage(img, x, y);
```
（`ctx.fillStyle = '#444'` の区切り線塗りはそのまま残す）

### 受入条件
1. 単一表示で「📷 PNG」→ 書き出された PNG に画面と同じ見た目の点線方眼が入っている（紙面色 #ECD2B3、方眼 #C2B2A1、左上角から 24 論理px = 出力 48px ピッチ、破線）。
2. 4面表示で「4ペイン全体」を選んで書き出し → 4面すべてに方眼が入り、ペイン間の区切り(#444)は従来どおり。
3. 事件ノート(preset)・全体/キャラ/メモの両系統で 1・2 を確認。オブジェクト（図形/テキスト/画像）は方眼の上に描かれる。

```html
    <meta property="og:title" content="魔法少女の魔女裁判 推理ノート" />
    <meta property="og:description" content="行動経路の作成・再生・推理ノートをブラウザで。データは端末内に保存されます。" />

    <meta property="og:image" content="https://REPLACE-WITH-PUBLIC-URL/logo.png" />
    <meta name="twitter:card" content="summary" />
```
注意:
- `og:image` は**絶対URL必須**なのでプレースホルダ（`REPLACE-WITH-PUBLIC-URL`）にし、ユーザーが URL 確定後に置換する。相対パスにしないこと。
- `logo.png` は正方形のため `twitter:card` は `summary`（大画像カード `summary_large_image` にしたければ 1200×630 の `public/ogp.png` を後日ユーザーが用意し、`og:image` を差し替える——手順書にこの旨を残す）。
- Tauri ビルドにも同じ index.html が使われるが meta は無害。

### ユーザー作業（チェックリストとして提示する）

1. **GitHub へ push**: リポジトリを GitHub（private でも可）に置く。`git remote -v` で未設定なら `gh repo create` → `git push -u origin main`。公開ブランチは main を推奨（作業ブランチをマージしてから）。
2. **Cloudflare アカウント作成** → ダッシュボード「Workers & Pages」→「Create」→「Pages」→「Connect to Git」→ リポジトリ選択。
3. **ビルド設定**: Framework preset = `Vite` / Build command = `npm run build` / Build output directory = `dist` / 環境変数 `NODE_VERSION=20`（Vite 7 は Node 20.19+ 必須）。
4. デプロイ完了で `https://<project>.pages.dev` が発行される。**この URL を index.html の `REPLACE-WITH-PUBLIC-URL`（2箇所）に置換してコミット→自動再デプロイ**。
5. **アクセス数計測**: Pages プロジェクト → 「Metrics」でリクエスト数は即見られる。ページビュー/訪問者数が欲しい場合は Cloudflare ダッシュボード「Analytics & Logs → Web Analytics」でサイトを追加し、Pages 連携の**自動セットアップ（スクリプト自動注入）**を有効化する（コード変更不要・Cookie 不使用なので同意バナーも不要）。以後ダッシュボードで訪問数・国・参照元が見られる。
6. **X へ投稿**: 発行 URL をポストに貼る。事前に [Card Validator 相当（実ポストのプレビュー）] でカード表示を確認（OGP はデプロイ後でないと反映されない）。
7. （任意）独自ドメインを買って Pages の Custom Domains に追加。
8. **動作確認**: 公開 URL をスマホ実機で開き、§B〜§D のモバイル機能と PWA インストール（ホーム画面に追加）を確認。

### 注意事項（手順書に必ず残す）
- **localhost で作ったデータは公開 URL には自動で移らない**（オリジン毎の localStorage/IndexedDB）。移したい場合はヘルプの「バックアップ書き出し → 読み込み」を使う（§G コード作業3の文言はこのため）。
- 本作は原作ゲームの二次創作物（キャラ画像等）を含む。**公開前に原作の二次創作ガイドラインの確認はユーザーの責任で行うこと**（特に広告収益化 §F は「営利利用」に該当し得る点に注意を促す）。
- デプロイは Web のみに影響し、Tauri デスクトップ版のビルド・動作には無関係。
