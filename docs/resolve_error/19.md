# 共通原因A: persist が set() のたびに全 state を同期直列化している（#4〜#7, #10, 過去の Chrome OOM の正体）

## A-0. メカニズム（証拠つき）

`src/store.ts` は zustand `persist` + `createJSONStorage(() => idbStorage)`。この構成では **`set()` が呼ばれるたびに** 次が同期実行される:

1. `partialize`（浅いコピー）→ **`JSON.stringify(全state)`**（createJSONStorage 内部・同期）
2. `idbStorage.setItem` 冒頭の `value === lastValue`（store.ts:261）— **巨大文字列同士の O(n) 比較**
3. 変更ありなら 500ms debounce 後の `writeNow`（store.ts:226）で `IDBObjectStore.put(巨大文字列)` — put は**引数の structured clone を同期実行**する

state が巨大なのは、Note の画像が `FileReader.readAsDataURL`（NoteView.tsx:293 の `processFile`）で **base64 data URL のまま `notes.*.assets` / `NoteObject.content` に保存**されるため（autocrop で 500px に縮小してもなお1枚 100KB〜600KB 級。全キャンバス合算で数MB〜数十MB）。

06/30 のプロファイルとの一致:
- `updateNoteObject store.ts:511` / `saveNoteHistory store.ts:398` が重い → 関数自体は浅いコピーのみ。**総時間の内訳は set() 内で走る persist の stringify**。saveNoteHistory が変える `noteHistory` は partialize 除外だが、**除外キーのみの変更でも stringify は毎回走り**、同一文字列比較（これも O(n)）で捨てられる。
- `lastValue store.ts:235:41` / `writeNow store.ts:226` → setItem クロージャ内の同一値比較と IDB put（structured clone）の実測コスト。
- #10 のプロファイルで `setSidebarWidth`(383) `setSkullMode`(380) `setGraphEditMode`(379) `setMode`(376) `setActiveFloor`(375) が**1件250〜650ms** → いずれも1フィールドの set()。**persist の全量 stringify を1回ずつ踏んでいる**。`changeModeWithTransition`（App.tsx:102）は set 3連発、AnimateView はマウント時に `setSidebarWidth`（AnimateView.tsx:112）を追加発火。
- 呼び出し側は**すでに間引き済み**: カラーピッカーは `commitThrottled`（NoteView.tsx:625, 100ms）、オブジェクトドラッグ中は Konva 直操作のみで store 非接触・コミットは dragEnd 1回（NoteView.tsx:1682-1706）。**保存層を直すのが正解**。

### 変更内容

`createJSONStorage` を廃止し、**オブジェクト参照を受け取る `PersistStorage<T>`** を自前実装する。新規 `src/persistStorage.ts`（store 分割後は `src/store/persistStorage.ts`）:

```ts
import { PersistStorage, StorageValue } from 'zustand/middleware';

const DB_NAME = 'mystery-map-db';
const STORE_NAME = 'app-state';
const PERSIST_DEBOUNCE_MS = 500;

// openDB / getItem の localStorage 移行 / removeItem は store.ts:179-278 から移設する。
// ※ P2 実施時は DB_VERSION=2 に上げるため、openDB は本ファイル1箇所に集約すること（後述の罠）。

// 保存状態インジケータ用（refactoring.md B-3）。未実装の間は no-op のまま。
export type PersistPhase = 'pending' | 'saving' | 'saved' | 'error';
let notifyPhase: (p: PersistPhase) => void = () => {};
export const setPersistPhaseListener = (fn: (p: PersistPhase) => void) => { notifyPhase = fn; };

export const createIdbPersistStorage = <S extends Record<string, unknown>>(): PersistStorage<S> & {
    flushNow: () => Promise<void>;   // バックアップ機能などが使う
} => {
    let pending: { name: string; value: StorageValue<S> } | null = null;
    let lastWritten: StorageValue<S> | null = null;
    let timer: ReturnType<typeof setTimeout> | null = null;

    // トップレベルキーの参照比較。partialize は毎回新オブジェクトを返すが、
    // 変更のなかったスライス（notes/presets/nodes…）は同一参照のままなので、
    // 「全キー同一参照」なら persist 対象に変化なし＝何もしない。O(キー数)。
    const changed = (prev: StorageValue<S> | null, next: StorageValue<S>): boolean => {
        if (!prev) return true;
        if (prev.version !== next.version) return true;
        const a = prev.state as Record<string, unknown>;
        const b = next.state as Record<string, unknown>;
        const keys = new Set([...Object.keys(a), ...Object.keys(b)]);
        for (const k of keys) if (!Object.is(a[k], b[k])) return true;
        return false;
    };

    const writeNow = async (): Promise<void> => {
        timer = null;
        if (!pending) return;
        const { name, value } = pending;
        pending = null;
        notifyPhase('saving');
        try {
            const str = JSON.stringify(value);          // ← 唯一の stringify 地点（最大1回/500ms）
            const db = await openDB();
            await new Promise<void>((resolve, reject) => {
                const tx = db.transaction(STORE_NAME, 'readwrite');
                tx.objectStore(STORE_NAME).put(str, name);
                tx.oncomplete = () => resolve();
                tx.onerror = () => reject(tx.error);
            });
            lastWritten = value;
            notifyPhase('saved');
        } catch {
            pending = { name, value };                   // 失敗時は次回リトライ
            notifyPhase('error');
        }
    };

    const schedule = () => {
        if (timer) clearTimeout(timer);
        timer = setTimeout(() => {
            if (typeof requestIdleCallback === 'function') {
                requestIdleCallback(() => { void writeNow(); }, { timeout: 1000 });
            } else {
                void writeNow();                         // WebView2 等のフォールバック
            }
        }, PERSIST_DEBOUNCE_MS);
    };

    const flushNow = async () => {
        if (timer) { clearTimeout(timer); timer = null; }
        await writeNow();
    };

    if (typeof window !== 'undefined') {
        window.addEventListener('visibilitychange', () => {
            if (document.visibilityState === 'hidden') void flushNow();
        });
        window.addEventListener('pagehide', () => { void flushNow(); });
    }

    return {
        getItem: async (name) => {
            const str = await idbGetString(name);        // 既存 getItem を移設（localStorage 移行込み）
            if (!str) return null;
            try { return JSON.parse(str) as StorageValue<S>; } catch { return null; }
        },
        setItem: (name, value) => {
            if (!changed(pending?.value ?? lastWritten, value)) return;  // 参照比較のみ
            notifyPhase('pending');
            pending = { name, value };
            schedule();
        },
        removeItem: async (name) => { /* 既存 removeItem を移設 */ },
        flushNow,
    };
};
```

## A-P2. base64 画像を state から追い出す（根治・中改修）

### 設計

**キー形式**: state には `asset://<id>` という文字列だけを置き、実体（Blob）は IndexedDB の別 objectStore に置く。

**⚠ 最重要の罠**: 現在 `openDB` は `indexedDB.open(DB_NAME, 1)`。objectStore 追加には **DB_VERSION=2** が必要で、同一 DB を別バージョンで開くモジュールが並存すると `VersionError`/blocked になる。**openDB を persistStorage.ts の1箇所に集約**し（P1 で移設済み）、そこで version 2 + 両ストア作成を行うこと:

```ts
const DB_VERSION = 2;
const ASSET_STORE = 'note-assets';
request.onupgradeneeded = (event) => {
    const db = (event.target as IDBOpenDBRequest).result;
    if (!db.objectStoreNames.contains(STORE_NAME)) db.createObjectStore(STORE_NAME);
    if (!db.objectStoreNames.contains(ASSET_STORE)) db.createObjectStore(ASSET_STORE);
};
```

新規 `src/services/assetStore.ts`:
```ts
export const isAssetKey = (src: string | undefined): src is string => !!src && src.startsWith('asset://');

export const putAsset = async (blob: Blob): Promise<string> => {
    const id = `asset_${Date.now()}_${Math.random().toString(36).slice(2, 8)}`;
    const db = await openDB();
    await txPut(db, ASSET_STORE, blob, id);
    return `asset://${id}`;
};
export const getAssetBlob = async (key: string): Promise<Blob | null> => { /* get(key.slice(8)) */ };
export const deleteAsset = async (key: string): Promise<void> => { /* delete */ };
export const listAssetKeys = async (): Promise<string[]> => { /* getAllKeys → asset:// 付与 */ };

// 非フック解決（getImageSizeFromUrl などの async 文脈用）
const urlCache = new Map<string, string>();               // asset key → object URL
export const resolveAssetUrl = async (src: string): Promise<string> => {
    if (!isAssetKey(src)) return src;                      // ./character/... や data: はそのまま
    const hit = urlCache.get(src);
    if (hit) return hit;
    const blob = await getAssetBlob(src);
    if (!blob) throw new Error(`missing asset: ${src}`);
    const url = URL.createObjectURL(blob);
    urlCache.set(src, url);
    return url;
};
```

新規 `src/hooks/useAssetUrl.ts`（表示用フック）:
```ts
export const useAssetUrl = (src: string | undefined): string | undefined => {
    const [url, setUrl] = useState<string | undefined>(() =>
        src && !isAssetKey(src) ? src : undefined);
    useEffect(() => {
        if (!src) { setUrl(undefined); return; }
        if (!isAssetKey(src)) { setUrl(src); return; }
        let alive = true;
        resolveAssetUrl(src).then(u => { if (alive) setUrl(u); }).catch(() => { if (alive) setUrl(undefined); });
        return () => { alive = false; };
    }, [src]);
    return url;
};
```

```ts
export const migrateDataUrlAssets = async (): Promise<void> => {
```

```ts
export const sweepOrphanAssets = async (): Promise<void> => {

// 起動時: migrateDataUrlAssets() → requestIdleCallback で sweepOrphanAssets()
```

## 2-2. tutorialBus（ローカル state の達成通知）

コンポーネントのローカル state（キャラ選択・クリップボード・4ペイントグル等）は store から見えないため、極小 pub/sub を新設する。

新規 `src/services/tutorialBus.ts`:
```ts
type Handler = () => void;
const handlers = new Map<string, Set<Handler>>();
export const tutorialBus = {
    emit(id: string): void { handlers.get(id)?.forEach(h => h()); },
    on(id: string, h: Handler): () => void {
        if (!handlers.has(id)) handlers.set(id, new Set());
        handlers.get(id)!.add(h);
        return () => handlers.get(id)?.delete(h);
    },
};
```

```ts
useEffect(() => {
```
