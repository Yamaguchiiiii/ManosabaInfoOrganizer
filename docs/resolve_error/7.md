## 問題1: Textオブジェクトをクリックしてもバウンディングボックスが表示されない

### 根本原因

05/16_15:00 の問題11修正（テキストの拡大縮小ハンドル削除）で、Transformer useEffect に以下のフィルタを追加した:

```typescript
.filter((node): node is Konva.Node => !!node && node.getClassName() !== 'Text');
```

このフィルタは **単独テキスト選択時にも適用される** ため、テキストをクリックしても `tr.nodes([])` になり、Transformerのバウンディングボックス（境界線）が一切表示されなくなった。フローティングツールバーは表示されるが、キャンバス上の選択フィードバックがゼロになっている。

### 修正対象ファイル

- `src/components/NoteView.tsx`

### 修正内容

Transformer useEffect のフィルタ条件を変更し、**単独テキスト選択時はテキストノードを含める**（ただし複数選択時はスケール変形防止のため除外を維持）:

```typescript
// 変更前
.filter((node): node is Konva.Node => !!node && node.getClassName() !== 'Text');

// 変更後
.filter((node): node is Konva.Node => {
    if (!node) return false;
    // 複数選択時: テキストをTransformerから除外（スケール変形防止）
    if (selectedIds.length > 1) return node.getClassName() !== 'Text';
    // 単独選択時: テキストも含める（バウンディングボックス表示のため）
    return true;
});
```

合わせて、Transformer コンポーネントにテキスト単独選択時のプロパティを動的設定する:

```tsx
const isOnlyText = selectedIds.length === 1 && selectedObject?.type === 'text';

<Transformer
    ref={(el) => { trRefs.current[index] = el; }}
    boundBoxFunc={(oldBox, newBox) => {
        if (newBox.width < 5 || newBox.height < 5) return oldBox;
        return newBox;
    }}
    keepRatio={
        selectedIds.length === 1 &&
        (selectedObject?.type === 'circle' || selectedObject?.type === 'triangle')
    }
    enabledAnchors={isOnlyText ? [] : undefined}
    rotateEnabled={!isOnlyText}
/>
```

これにより、テキスト単独選択時は **リサイズ・回転ハンドルなしの選択ボーダーのみ** が表示される。

## 問題2: Text+他オブジェクトのグループ化が視覚的に機能しない

### 根本原因

問題1の副作用。複数選択（テキスト＋図形）時に Transformer はテキストを除外するため、Transformer のバウンディングボックスには図形のみ含まれる。グループ化操作自体（`groupId` の設定）は正しく動作するが、テキストに選択インジケーターが表示されないためユーザーには「テキストが選択に含まれていない」「グループ化されていない」と見える。

また、グループ化後にテキストをクリックすると `onSelect` → `obj.groupId` チェック → グループ全員選択 という流れは正しく動作するが、その結果としてテキストのバウンディングボックスが表示されないため、グループ選択が機能していないように見える。

### 修正対象ファイル

- `src/components/NoteView.tsx`

### 修正内容

複数選択時にテキストノードが Transformer から除外される代わりに、選択中のテキストオブジェクトに対して **Konva Layer 上にカスタム選択インジケーター Rect を描画する**:

```tsx
{/* 複数選択時、テキストノードの選択インジケーター（Transformer 対象外のため個別描画） */}
{selectedIds.length > 1 && objs
    .filter(o => o.type === 'text' && selectedIds.includes(o.id))
    .map(o => (
        <Rect
            key={`sel_indicator_${o.id}`}
            x={(o.x ?? 0) - 2}
            y={(o.y ?? 0) - 2}
            width={(o.width || 150) + 4}
            height={(o.fontSize || 24) * 1.5 + 4}
            stroke="#007acc"
            strokeWidth={1 / scale}
            dash={[4 / scale, 4 / scale]}
            fill="transparent"
            listening={false}
        />
    ))
}
```

この Rect は `listening={false}` のため、クリックイベントを妨げない。テキストの実際の描画サイズはKonaのText nodeが決定するため、`width` はデフォルト幅（150）で近似する。問題1の修正（単独テキスト選択時のTransformerバウンディングボックス）と組み合わせることで、単独・複数選択・グループ選択いずれの場合もテキストの選択状態が視覚的にわかる。

## 問題3: キャラクターページのデフォルト配置画像・位置が誤っている

### 根本原因

`NoteView.tsx` の `useEffect` でキャラクターページを初期化する際:

```typescript
// 現在の実装
const defaultImgSrc = `./icon/${selectedChar}`;   // ← 小サイズアイコン画像
addNoteAsset('character', selectedChar, defaultImgSrc);
getImageSizeFromUrl(defaultImgSrc, 500).then(size => {
    addNoteObject('character', selectedChar, {
        ...
        x: 50, y: 100,    // ← 左上固定
        width: size.width, height: size.height,
        ...
    });
});
```

- **画像パス**: `./icon/` は 40×40px 程度のサムネイルアイコン。フルサイズのキャラクター画像は `./character/` にある。
- **配置位置**: `x: 50, y: 100` は左上領域への固定配置。「左下にキャラクターの上半身が見える」位置（キャンバス下端からheight/2だけ上）に配置すべきところが誤っている。

### 修正対象ファイル

- `src/components/NoteView.tsx`

### 修正内容

```typescript
// 変更後
const defaultImgSrc = `./character/${selectedChar}`;   // ← フルサイズキャラクター画像
addNoteAsset('character', selectedChar, defaultImgSrc);
getImageSizeFromUrl(defaultImgSrc, 800).then(size => {   // ← maxDimension を 800 に拡大
    // キャンバスの論理高さを近似値 600 として左下に上半身が見える位置に配置
    // y = canvasLogicalHeight - size.height / 2 → 下半分がキャンバス外に出る
    const canvasLogicalHeight = 600;
    addNoteObject('character', selectedChar, {
        id: `default_char_${Date.now()}`,
        type: 'image',
        x: 0,
        y: canvasLogicalHeight - size.height / 2,
        width: size.width,
        height: size.height,
        content: defaultImgSrc,
        rotation: 0, scaleX: 1, scaleY: 1,
        canvasIndex: 0
    });
});
```

`canvasLogicalHeight = 600` はキャンバスの論理座標系における近似高さ。Konva Stage の `scaleX/scaleY` で実際の画面サイズに合わせてスケールされるため、実用上は妥当な値。より正確にするには、キャラクターキャンバス用の `canvasSize` を `NoteView` まで持ち上げる設計変更が必要（現在は `CanvasWorkspace` 内部に閉じている）が、初期配置の近似としてこの値で対応する。

## 問題4: グループ化されたオブジェクト移動後の Undo 挙動が正しくない

### 根本原因

05/16_15:00 問題6の修正で導入した `debouncedSaveHistory` の実装に誤りがある。

`saveNoteHistory()` は **呼び出し時点の現在 `notes` を履歴に追加する**。しかし `debouncedSaveHistory` は `updateNoteObject(skipHistory=true)` で状態更新した **後** に非同期（100ms 遅延）で呼び出されるため、**変更後の状態 S2 が履歴に積まれる**。

状態遷移のトレース:
```
操作          | 内部で発生すること                        | 履歴 (noteHistory)      | 現在状態
-------------|------------------------------------------|------------------------|--------
初期状態 S0   | -                                        | []                     | S0
Ctrl+G        | updateNoteObjects が内部で saveNoteHistory | [S0]                   | S1 (grouped)
A をドラッグ  | updateNoteObject(true) → state = S2       | [S0]                   | S2 (moved)
100ms 後      | debouncedSaveHistory → save 現在状態 S2   | [S0, S2]               | S2
Ctrl+Z #1    | restore S2 (= 現在と同じ)                 | [S0]                   | S2 (変化なし！)
Ctrl+Z #2    | restore S0                                | []                     | S0 (移動もグループ化も戻る)
```

**1回目の Ctrl+Z で何も起こらず、2回目で移動とグループ化が一緒に解除される**原因はこの二重保存（S2が履歴にも現在状態にも存在する）にある。

### 修正対象ファイル

- `src/components/NoteView.tsx`

### 修正内容

`debouncedSaveHistory`（変更後に保存）を廃止し、**変更前に1回だけ保存する** `saveHistoryOnceThenSkip` パターンに変更する。

```typescript
// 変更前（誤り: 変更後に保存）
const saveHistoryDebounceRef = useRef<ReturnType<typeof setTimeout> | null>(null);
const debouncedSaveHistory = () => {
    if (saveHistoryDebounceRef.current) clearTimeout(saveHistoryDebounceRef.current);
    saveHistoryDebounceRef.current = setTimeout(() => { saveNoteHistory(); }, 100);
};

// 変更後（正しい: 変更前に1回だけ保存）
const batchSaveRef = useRef<ReturnType<typeof setTimeout> | null>(null);
const saveHistoryOnceThenSkip = () => {
    if (!batchSaveRef.current) {
        // バッチ先頭: 変更前の現在状態を保存
        saveNoteHistory();
    } else {
        clearTimeout(batchSaveRef.current);
    }
    // 300ms 後にバッチをリセット（次のドラッグ開始を新バッチとして検出するため）
    batchSaveRef.current = setTimeout(() => {
        batchSaveRef.current = null;
    }, 300);
};
```

`onChange` プロップを更新:

```typescript
// 変更後
onChange: (newAttrs: NoteObject) => {
    saveHistoryOnceThenSkip();  // 変更前の状態を1回だけ保存（バッチ先頭のみ）
    updateNoteObject(targetType, displayTargetId, obj.id, newAttrs, true);  // skipHistory=true
},
```

修正後の状態遷移:
```
操作          | 内部で発生すること                               | 履歴 (noteHistory) | 現在状態
-------------|------------------------------------------------|-------------------|--------
初期状態 S0   | -                                              | []                | S0
Ctrl+G        | updateNoteObjects が内部で saveNoteHistory(S0)  | [S0]              | S1 (grouped)
A をドラッグ  | saveHistoryOnceThenSkip → save 現在状態 S1      | [S0, S1]          | S1
              | updateNoteObject(true) → state = S2             | [S0, S1]          | S2 (moved)
Ctrl+Z #1    | restore S1 (grouped, 移動前)                   | [S0]              | S1 ✓
Ctrl+Z #2    | restore S0 (ungrouped)                         | []                | S0 ✓
```

なお、`saveHistoryDebounceRef` の名前を `batchSaveRef` に変更することで可読性が向上する。既存の `saveHistoryDebounceRef` を宣言している行も合わせて削除・置き換えること。

## 問題5: フリーライティングの補正強さをスライダーで調節できない

### 根本原因

`freehandSettings.stabilization` の UI が `<select>` による4段階固定値（0/1/2/3）になっている。compact pad と char-sidebar の両方に同じ実装がある。

```tsx

<select value={freehandSettings.stabilization}
    onChange={e => setFreehandSettings(s => ({ ...s, stabilization: +e.target.value }))}>
    <option value={0}>補正: なし</option>
    <option value={1}>補正: 弱</option>
    <option value={2}>補正: 中</option>
    <option value={3}>補正: 強</option>

```

### 修正対象ファイル

- `src/components/NoteView.tsx`

`<select>` を `<input type="range">` に変更する（compact pad と char-sidebar の両箇所）。`strokeWidth` スライダーと同じパターンを踏襲する。`stabilization` の上限は Chaikin アルゴリズムの反復回数であり、5以上は計算負荷が増すため max=5 とする。

**compact pad（renderPortalUI 内）の変更:**

## 問題6: ○と△のドラッグ配置で表示位置が最初のクリック点になる

### 根本原因

Konva の `Circle` と `RegularPolygon` は `x, y` を **図形の中心座標** として扱う。しかし `handleStageMouseUp` の isDrag ケースでは、生成する `NoteObject` の `x, y` に `drawingShapeInfoRef.current.x/y`（= ドラッグバウンディングボックスの **左上** 座標）をそのまま使用している:

```typescript
// handleStageMouseUp isDrag ケース（現在）
newObj = {
    id: baseId,
    type: type as NoteObjectType,
    x: drawingShapeInfoRef.current.x as number,   // ← バウンディングボックス左上 X
    y: drawingShapeInfoRef.current.y as number,   // ← バウンディングボックス左上 Y
    width: dragW,
    height: dragH,
    ...
};
```

`ShapeObject` はこの `x, y` を `commonProps.x/y` として各 Konva ノードに渡す:
- `<Rect>`: `x, y` = 左上座標 → **問題なし**（Rect は左上基準）
- `<Circle>`: `x, y` = **中心**座標 → 円の中心がバウンディングボックス左上に来てしまう
- `<RegularPolygon>`: `x, y` = **中心**座標 → 同様

結果として、`○` と `△` はドラッグしたバウンディングボックスの左上（= 最初にクリックした点）を中心に描画される。

### 修正対象ファイル

- `src/components/NoteView.tsx`

### 修正内容

isDrag ケースで `circle` / `triangle` の場合のみ、`x, y` をバウンディングボックスの **中心座標** に変換する:

```typescript
// handleStageMouseUp isDrag ケース（変更後）
const isCentered = type === 'circle' || type === 'triangle';
newObj = {
    id: baseId,
    type: type as NoteObjectType,
    x: isCentered
        ? (drawingShapeInfoRef.current.x as number) + dragW / 2   // 中心 X
        : (drawingShapeInfoRef.current.x as number),              // 左上 X (rect/image)
    y: isCentered
        ? (drawingShapeInfoRef.current.y as number) + dragH / 2   // 中心 Y
        : (drawingShapeInfoRef.current.y as number),              // 左上 Y (rect/image)
    width: dragW,
    height: dragH,
    fill: '#A8D5BA',
    stroke: '#000000',
    strokeWidth: 2,
    rotation: 0, scaleX: 1, scaleY: 1,
    canvasIndex: index,
    content: type === 'image' ? drawingShapeInfoRef.current.content as string : undefined,
};
```

これにより、ドラッグで描いたバウンディングボックスの中心に `Circle` / `RegularPolygon` の中心が置かれ、視覚上のバウンディングボックスとKonaのレンダリングが一致する。
