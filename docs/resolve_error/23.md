## 前提知識: なぜタッチで Konva の onClick が発火しないのか（§A/§C-1/§C-2 共通の土台）

本プロジェクトの `konva` は **v10.0.12**（package.json `"konva": "^10.0.12"`）。実装確認済みの事実（`node_modules/konva/lib/Stage.js`）:

1. Stage は DOM の `touchstart/touchmove/touchend` を `_pointerdown/_pointermove/_pointerup` に束ね、イベント種別ごとのマップ `EVENTS_MAP` で発火するイベント名を決める。
   - mouse 系: `pointerclick: 'click'`, `pointerdblclick: 'dblclick'`
   - **touch 系: `pointerclick: 'tap'`, `pointerdblclick: 'dbltap'`** ← タッチでは `click` は**一切発火しない**
2. さらに `_pointerdown` 内で、ヒットした shape の `preventDefault` 属性（既定 true）により **`evt.preventDefault()` が呼ばれる**（`{ passive: false }` で登録済み）。これによりブラウザが touchend 後に合成する互換 mouse イベント（mousedown→mouseup→click）も**抑止される**。
3. 結論: タッチ端末では「Konva の `click` も」「ブラウザ合成の `click` も」発生しない。**タッチで反応させるには `tap`（react-konva では `onTap`）を登録する必要がある。**
4. react-konva の型（`node_modules/react-konva/lib/ReactKonvaCore.d.ts`）:
   - `onClick?(evt: Konva.KonvaEventObject<MouseEvent>): void;`
   - `onTap?(evt: Konva.KonvaEventObject<TouchEvent>): void;`
   - 同一ハンドラを両方に渡すため、ハンドラ側の引数型は `Konva.KonvaEventObject<MouseEvent | TouchEvent>` にする（インターフェースがメソッド記法なので bivariance により代入可能。tsc で通ることを確認すること）。

## §A 【症状1】スマホ Create でマップ上の地点をタップしても反応しない

### 原因（推測ではなく確定。3層ある）

**原因1（主因）: マップの Stage / ノードに `onClick` しか登録されておらず、タッチでは発火しない。**

- `src/components/CreateView.tsx` L109（grep: `onClick={(e) => onStageClick(e, floorId)}`）: FloorPane の Stage は `onClick` と `onMouseMove` のみ。
- `src/components/create/MapObjectLayer.tsx` L180（grep: `onClick: (e: Konva.KonvaEventObject<MouseEvent>) => onNodeClick(e, node.id),`）: ノード共通 props も `onClick` のみ。
- 上記「前提知識」の通り、タッチでは `tap` しか来ないため、経路モードのノードタップ（waypoint 追加）もグラフ編集モードのノード追加/連結も一切動かない。

**原因2: 仮に `onTap` を配線しても、`e.evt.button !== 0` ガードで TouchEvent が弾かれる。**

- `CreateView.tsx` L234（grep: `if (e.evt.button !== 0) return;` — handleStageClick 内）
- `CreateView.tsx` L288（grep: 同上 — handleNodeClick 内）
- `TouchEvent` に `button` プロパティは無く `undefined !== 0` が真になり早期 return する。`e.evt.button === 2`（右クリック判定、L228/L274）も TouchEvent では判定不能。**MouseEvent のときだけ button を見る**よう直す必要がある。

**原因3（実用上の第2主因）: ノードの当たり判定が物理 4px 程度しかなく、イベントを直しても実際にはほぼ押せない。**

- マップ自然サイズは floor_1.png = **1406×761**（floor_2: 1239×587, floor_b1: 1031×589）。
- モバイル FloorPane はズーム無しの fit 表示（`CreateView.tsx` L84 grep: `const fitScale = (mapNat.w > 0`）。幅375pxの端末では `fitScale ≈ 371/1406 ≈ 0.264`。
- PassNode は `radius={5} hitStrokeWidth={20}`（`src/components/common/MapElements.tsx` L98-99）→ ヒット半径 = 5 + 20/2 = 15（マップ論理px）→ **物理 15 × 0.264 ≈ 4px**。RoomNode/StairNode も同程度。指のタップ（推奨44px）ではまず当たらない。
- → タッチ時はヒット領域を**物理 22px 半径（直径44px）相当**へ底上げする（A-3）。

## §B 【症状2】地点入力欄（Start/Via/Goal）タップでソフトキーボードを出さない

### 原因と方針

- `src/components/create/WaypointPanel.tsx` L158-164（grep: `placeholder={index === 0 ? "Start..."`）の `<input type="text">` にフォーカスが入ると OS が仮想キーボードを出す。
- モバイルの地点入力は「フォーカス → 候補一覧（NodeCandidateList）から選ぶ / マップをタップする」設計（`variant='dock'` で候補が自動展開、`onFocus` → `setSuggestionTargetIndex`）であり、手入力は必須でない。
- 対応: **`inputMode="none"`** をモバイルのみ付与する。フォーカス・キャレット・`onFocus` は従来どおり動くのでターゲット強調（`.is-target`）と候補展開は維持される。iOS Safari 12.2+ / Android Chrome 66+ 対応。
  - `readOnly` は使わない（iOS で readonly input はタップでフォーカスが入らないことがあり、候補展開のトリガー `onFocus` が死ぬ）。
  - 判定は既存の `useViewport()` を使う（`window.__TAURI__` 等の直接判定はしない。CLAUDE.md 準拠）。

### 修正手順（`WaypointPanel.tsx`）

**(1)** import 追加:

```ts
import { useViewport } from '../../hooks/useViewport';
```

**(2)** コンポーネント冒頭（grep: `const [collapsed, setCollapsed] = useState`）の直後:

```ts

    // フォーカス自体は通す(is-target 強調と候補展開に必要)。#23-B
```

**(3)** 地点入力 input（grep: `onFocus={() => setSuggestionTargetIndex(index)}` の直下の input）へ属性追加:

### C-1 マップがピンチズーム/パンできず、fit 固定の極小表示のまま精密操作を強いられる

**症状:** モバイル Create のマップは常に「ペインにフィット」の縮小表示（375px幅で約0.26倍）。ノード密集部で目的の地点を選べず、部屋名も判読不能。ズーム手段が無い（`useStageZoom` はホイール専用でどこにも触られていない）。

**原因:** `CreateView.tsx` FloorPane はズームを持たない設計（L68 コメント `#06/28-6:04-1: 4ペインのマップはズーム不要`）。デスクトップ4ペインでは正しいが、モバイル単一ペインには不適。

**修正:** FloorPane に「2本指ピンチズーム + 2本指パン」を追加する（1本指は従来どおりタップ/ノードドラッグに温存 → タップ操作と衝突しない）。`interactiveZoom`（§A-3 で導入済み）が true のときだけ有効。**以下が §A 適用後の FloorPane 完成形**（`const FloorPane: React.FC<FloorPaneProps> = ({...}) => {` から return 直前まで差し替え。既存の containerRef/size/mapNat/useEffect はそのまま）:

```tsx
const FloorPane: React.FC<FloorPaneProps> = ({
    floorId, label, isActive, onHover,
    nodes, nodeMap, edges, isGraphEditMode, mode,
    displaySegments, displayPath, connectingNodeId, hoveredNodeId, waypoints, dynamicEdgeRef,
    onStageClick, onStageMouseMove, onNodeClick, onNodeMouseEnter, onNodeMouseLeave,
    onNodeDragMove, onNodeDragEnd, onEdgeContextMenu,
    onNodeTouchStart, onNodeTouchEnd, onEdgeTouchStart, onEdgeTouchEnd,   // C-2 で追加
    interactiveZoom,
}) => {
    const containerRef = useRef<HTMLDivElement>(null);
    const [size, setSize] = useState({ width: 0, height: 0 });
    const [mapNat, setMapNat] = useState({ w: 0, h: 0 });
    // （既存の ResizeObserver useEffect はそのまま）

    const fitScale = (mapNat.w > 0 && mapNat.h > 0 && size.width > 0 && size.height > 0)
        ? Math.min(size.width / mapNat.w, size.height / mapNat.h) : 1;
    const fitX = (size.width - mapNat.w * fitScale) / 2;
    const fitY = (size.height - mapNat.h * fitScale) / 2;

    // C-1: モバイルの2本指ピンチズーム/パン。null = fit 表示（従来）。
    const [view, setView] = useState<{ scale: number; x: number; y: number } | null>(null);
    const lastCenterRef = useRef<{ x: number; y: number } | null>(null);
    const lastDistRef = useRef(0);
    useEffect(() => { setView(null); lastCenterRef.current = null; lastDistRef.current = 0; }, [floorId]);

    const handleTouchMove = (e: Konva.KonvaEventObject<TouchEvent>) => {
        if (!interactiveZoom || e.evt.touches.length < 2) {
            onStageMouseMove(e);   // 1本指: 連結中の動的エッジ線プレビュー（従来動作）
            return;
        }
        e.evt.preventDefault();
        const stage = e.target.getStage();
        if (!stage) return;
        // ピンチ操作中および直後の tap を握りつぶす（指を離した瞬間の誤タップ防止）#23-A
        stage.setAttr('suppressTapUntil', Date.now() + 400);
        const t1 = e.evt.touches[0], t2 = e.evt.touches[1];
        const center = { x: (t1.clientX + t2.clientX) / 2, y: (t1.clientY + t2.clientY) / 2 };
        const dist = Math.hypot(t2.clientX - t1.clientX, t2.clientY - t1.clientY);
        if (!lastCenterRef.current || lastDistRef.current === 0) {
            lastCenterRef.current = center;
            lastDistRef.current = dist;
            return;
        }
        const cur = view ?? { scale: fitScale, x: fitX, y: fitY };
        const newScale = Math.min(Math.max(cur.scale * (dist / lastDistRef.current), fitScale), fitScale * 8);
        const rect = stage.container().getBoundingClientRect();
        const centerOnStage = { x: center.x - rect.left, y: center.y - rect.top };
        // ピンチ中心を不動点にズームし、中心の移動分だけパンする
        const pointTo = { x: (centerOnStage.x - cur.x) / cur.scale, y: (centerOnStage.y - cur.y) / cur.scale };
        const dx = center.x - lastCenterRef.current.x;
        const dy = center.y - lastCenterRef.current.y;
        setView({ scale: newScale, x: centerOnStage.x - pointTo.x * newScale + dx, y: centerOnStage.y - pointTo.y * newScale + dy });
        lastCenterRef.current = center;
        lastDistRef.current = dist;
    };
    const handleTouchEnd = (e: Konva.KonvaEventObject<TouchEvent>) => {
        if (e.evt.touches.length < 2) { lastCenterRef.current = null; lastDistRef.current = 0; }
    };

    const effScale = view?.scale ?? fitScale;
    const effX = view?.x ?? fitX;
    const effY = view?.y ?? fitY;

    const showDynamic = isGraphEditMode && !!connectingNodeId && nodeMap[connectingNodeId]?.floor === floorId;

    return (
        <div
            ref={containerRef}
            onMouseEnter={() => onHover(floorId)}
            onPointerDown={() => onHover(floorId)}
            style={{
                position: 'relative', width: '100%', height: '100%', overflow: 'hidden',
                background: '#222', boxSizing: 'border-box',
                border: isActive ? '2px solid #007acc' : '2px solid #333'
            }}
        >
            <div style={{ position: 'absolute', top: 6, left: 6, zIndex: 5, background: 'rgba(0,0,0,0.6)', color: '#fff', padding: '3px 8px', borderRadius: 4, fontSize: 12, pointerEvents: 'none' }}>
                {label}
            </div>
            {interactiveZoom && view && (
                <button
                    className="floorpane-zoom-reset"
                    onClick={() => setView(null)}
                    title="表示をリセット"
                    aria-label="ズームをリセット"
                >⤢</button>
            )}
            {size.width > 0 && size.height > 0 && (
                <Stage
                    width={size.width} height={size.height}
                    scaleX={effScale} scaleY={effScale} x={effX} y={effY}
                    onClick={(e) => onStageClick(e, floorId)}
                    onTap={(e) => onStageClick(e, floorId)}
                    onMouseMove={onStageMouseMove}
                    onTouchMove={handleTouchMove}
                    onTouchEnd={handleTouchEnd}
                    onContextMenu={(e) => e.evt.preventDefault()}
                    style={{ cursor: isGraphEditMode ? 'crosshair' : 'default' }}
                >
                    <Layer>
                        <MapImage src={mapSrcFor(floorId)} onLoad={(w, h) => setMapNat(prev => (prev.w === w && prev.h === h) ? prev : { w, h })} />
                        <MapObjectLayer
                            nodes={nodes}
                            nodeMap={nodeMap}
                            edges={edges} activeFloor={floorId}
                            isGraphEditMode={isGraphEditMode} mode={mode}
                            pathSegments={isGraphEditMode ? [] : displaySegments}
                            highlightedPath={isGraphEditMode ? [] : displayPath}
                            connectingNodeId={connectingNodeId} hoveredNodeId={hoveredNodeId}
                            waypoints={waypoints} handleEdgeContextMenu={onEdgeContextMenu}
                            onNodeClick={(e, nodeId) => onNodeClick(e, nodeId, floorId)}
                            onNodeMouseEnter={onNodeMouseEnter}
                            onNodeMouseLeave={onNodeMouseLeave}
                            onNodeDragMove={onNodeDragMove}
                            onNodeDragEnd={onNodeDragEnd}
                            onNodeTouchStart={onNodeTouchStart}
                            onNodeTouchEnd={onNodeTouchEnd}
                            onEdgeTouchStart={onEdgeTouchStart}
                            onEdgeTouchEnd={onEdgeTouchEnd}
                            touchHitScale={interactiveZoom ? effScale : undefined}
                            showNodeNames={interactiveZoom}
                        />
                        {/* showDynamic の Line は既存のまま */}
                    </Layer>
                </Stage>
            )}
        </div>
    );
};
```

### C-2 ノード編集/削除・エッジ削除が右クリック前提でモバイルでは不可能

**症状:** ノードの名前・種別変更（NodeEditModal）はノード右クリック（`handleNodeClick` の `button === 2` 分岐）、エッジ削除は `onContextMenu`（`MapObjectLayer.tsx` L82）のみ。タッチには右クリックが無く、しかも Konva が touchstart で `preventDefault()` するため **Android の長押し contextmenu も発火しない**（iOS はそもそも canvas で contextmenu を出さない）。つまりモバイルではマップグラフのメンテナンスが一切できない。

**修正:** グラフ編集モード中の**長押し（500ms）**を右クリック相当にする。

**(1)** `CreateView.tsx` — 長押しハンドラを追加（`handleEdgeContextMenu` の近く）:

```ts
  // C-2: タッチの長押しを右クリック相当にする（ノード=編集モーダル / エッジ=削除確認）。
  // 長押し成立時は stage attr で後続の tap を握りつぶす（§A の isTapSuppressed が見る）。
  const nodePressRef = useRef<number | null>(null);
  const edgePressRef = useRef<number | null>(null);
  const cancelNodePress = useCallback(() => {
      if (nodePressRef.current !== null) { window.clearTimeout(nodePressRef.current); nodePressRef.current = null; }
  }, []);
  const cancelEdgePress = useCallback(() => {
      if (edgePressRef.current !== null) { window.clearTimeout(edgePressRef.current); edgePressRef.current = null; }
  }, []);

  const handleNodeTouchStart = useCallback((e: Konva.KonvaEventObject<TouchEvent>, nodeId: string) => {
      if (!isGraphEditMode) return;
      const stage = e.target.getStage();
      cancelNodePress();
      nodePressRef.current = window.setTimeout(() => {
          nodePressRef.current = null;
          stage?.setAttr('suppressTapUntil', Date.now() + 600);
          const node = nodeMap[nodeId];
          if (node) setEditingNode(node);
      }, 500);
  }, [isGraphEditMode, nodeMap, cancelNodePress]);

  const handleEdgeTouchStart = useCallback((e: Konva.KonvaEventObject<TouchEvent>, edgeId: string) => {
      if (!isGraphEditMode) return;
      const stage = e.target.getStage();
      cancelEdgePress();
      edgePressRef.current = window.setTimeout(() => {
          edgePressRef.current = null;
          stage?.setAttr('suppressTapUntil', Date.now() + 600);
          void (async () => {
              if (await showConfirm('この通路(エッジ)を削除しますか？')) removeEdge(edgeId);
          })();
      }, 500);
  }, [isGraphEditMode, removeEdge, showConfirm, cancelEdgePress]);
```

### C-6 iOS で入力欄フォーカス時に画面が勝手にズームする

**症状:** iOS Safari は **font-size < 16px** の input にフォーカスすると自動でページズームする。滞在秒数（`__stay-input`、`--fs-xs`）・開始条件の delay 入力・Note 検索などが該当し、フォーカスのたびに画面が拡大し、戻らないことがある。

**修正:** `index.html` L6（grep: `<meta name="viewport"`）を差し替え（C-7 と同一行）:

```html
    <meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, viewport-fit=cover" />
```

- iOS は `maximum-scale=1` を「フォーカス時自動ズームの抑止」にのみ適用し、ユーザーのピンチズームはアクセシビリティ上無視して引き続き可能（iOS 10+）。
- Android Chrome では `maximum-scale=1` がページのピンチズームを禁止する。本アプリは canvas 側に独自ズーム（C-1）を持つ app-like UI で `body` も `overflow: hidden` のため許容する。もしページズームを残したい場合の代替案は「モバイルの全 input を `font-size: 16px` 以上にする」（C-9 の `@media (pointer: coarse)` ブロックに含めてあるので、両方入れれば将来 `maximum-scale` を外しても再発しない）。

**受入条件:** iOS 実機（または Safari Responsive Design Mode）で滞在秒数 input にフォーカスしてもページが拡大しない。

### C-9 経路パネル内のボタン/入力がタッチには小さすぎる（22px〜30px）

### C-13 スマホ横向き（例 812×375）で 'tablet' 判定になりデスクトップUIが出て操作不能級になる

**症状:** `useViewport.ts` は `innerWidth` のみで判定（<768 mobile）。スマホを横に持つと幅 812 → 'tablet' → **デスクトップレイアウト**（NavRail + 4ペイン + RouteDock）が高さ375pxに詰め込まれ、実用不能。

**修正:** `useViewport.ts` の `compute` を差し替え:

```ts
const compute = (): Viewport => {
    if (typeof window === 'undefined') return 'desktop';
    const w = window.innerWidth;
    const h = window.innerHeight;
    // 横向きスマホ対策: 主ポインタが指(coarse)かつ高さが極端に低い端末は幅に関わらず mobile。
    // w < 1000 の条件でタブレット横(1024+)を除外する。
    const coarse = typeof window.matchMedia === 'function' && window.matchMedia('(pointer: coarse)').matches;
    if (w < 768 || (coarse && h < 500 && w < 1000)) return 'mobile';
    if (w < 1100) return 'tablet';
    return 'desktop';
};
```

- 補足: Android のソフトキーボードは既定で layout viewport（innerHeight）を縮めない（visual viewport のみ）ため、キーボード表示で判定が揺れることは基本無い。万一揺れる端末があっても §B でキーボード自体を抑止している。
- モバイル横向きは「縦積みレイアウトのまま」になる（マップ+dock が窮屈だが操作可能）。横向き専用レイアウトは本件のスコープ外。

**受入条件:** DevTools で 812×375（横向き iPhone）にすると MobileShell（下タブ）が出る。768×1024（iPad 縦）は tablet、1024×768（iPad 横）は tablet のまま。デスクトップ判定に変化なし。

### C-15 iOS でボタン連打時にダブルタップズーム/誤拡大が発生する

**症状:** iOS Safari はダブルタップズームを持ち、`touch-action: manipulation` の無い要素の素早い連続タップ（フロア切替、+ Add Stop、Undo 連打など）で画面が拡大しうる。canvas は `.konvajs-content { touch-action: none; }` 済み（App.scss L74）だが DOM UI が未対応。C-6 の `maximum-scale=1` を入れても、将来外した場合に再発する。

**修正:** App.scss のグローバル節（`button, a, input, select, textarea, [tabindex], [role="button"]` の focus-visible ルール付近）に追加:

```scss
// C-15: ダブルタップズームを無効化し、タップの認識も速くする（スクロール/ピンチは阻害しない）
button, a, select, label, input, [role='button'], [tabindex] {
  touch-action: manipulation;
}
```

**受入条件:** フロアセグメントや + Add Stop を高速連打してもページが拡大しない。スクロール可能領域のスワイプは従来どおり。

## 補足（15件外・任意の軽微改善）

実装は任意。やる場合も各1行〜数行。

- **theme-color meta 欠如**: PWA manifest には `theme_color: "#1e1e1e"`（vite.config.ts L39）があるが、通常タブ用の `<meta name="theme-color" content="#1e1e1e">` が index.html に無く、モバイルブラウザの UI 色が合わない。head に1行追加。
