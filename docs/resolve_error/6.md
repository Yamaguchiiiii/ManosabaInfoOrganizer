## 問題1: Chrome 上でカクつき + OOM（Chromeのみ）

### 根本原因

#### 原因A: RAF ループ内での毎フレームオブジェクト生成（OOMの直因）

`useAnimationPositions.ts` の `animate()` 関数が 60fps で実行されるたびに以下を生成する:

```typescript
// 毎フレーム生成（60fps × 複数オブジェクト = 毎秒数千個のGC対象オブジェクト）
const activePositions: ActivePosition[] = [];
const targets: Record<string, { x: number; y: number; floor: string; isFinished: boolean }> = {};
```

さらに `getCollisionOffsets`（`animationUtils.ts`）内でも毎フレーム:

```typescript
const parent = Array.from({ length: n }, (_, i) => i);  // 新規配列
const groups: Record<number, number[]> = {};              // 新規オブジェクト
const offsets: Record<string, { x: number, y: number }> = {};  // 新規オブジェクト
```

Chrome の V8 GC（世代別 GC）は Minor GC を頻繁に走らせるが、タブごとのレンダラープロセスに対して Edge より厳しいメモリ上限を設定しているため、GC が追いつかない場合に OOM → タブクラッシュが発生する。Edge（同じ Chromium ベース）はレンダラープロセスのメモリ上限が緩いため同症状が出にくい。

#### 原因B: `shadowBlur` による GPU メモリ蓄積（カクつきの補助原因）

`AnimateView.tsx` の `MovingCharIcon` に `shadowBlur={6}` が設定された `KonvaImage` が 15キャラ × 3フロア = **45インスタンス** 存在する。Konva は shadow 付きノードに対して GPU コンポジット専用バッファを割り当てる。Chrome はこれを積極的にキャッシュするため VRAM 使用量が増加し続け、長時間再生で GC スパイクが生じる。

### 修正対象ファイル

- `src/hooks/useAnimationPositions.ts`
- `src/utils/animationUtils.ts`

### 修正内容

`getCollisionOffsets` を毎回オブジェクトを生成しないように変更する。`parent` 配列を引数として受け取るか、固定長の Int32Array を使用する:

```typescript

const _parent = new Int32Array(20);
const _offsets: Record<string, { x: number; y: number }> = {};

    positions: PositionWithVelocity[],
    iconSize: number

    const n = positions.length;

    for (let i = 0; i < n; i++) _parent[i] = i;

    // offsets を再利用（既存キーを上書き）

        if (!_offsets[p.id]) _offsets[p.id] = { x: 0, y: 0 };
        _offsets[p.id].x = 0;
        _offsets[p.id].y = 0;
    });

    // groups は Map で管理し再利用（または groups オブジェクトのプロパティを毎回リセット）

    // ...以降は既存ロジック（_offsets に書き込む）...

    return _offsets;
};
```

## 問題6: グループ化/複数選択オブジェクトの Undo が1個ずつ戻る

### 根本原因

`ShapeObject` / `URLImage` / `EditableText` の `onDragEnd` が以下を呼ぶ:

```typescript
onDragEnd: (e: any) => onChange({ x: e.target.x(), y: e.target.y() })
```

`onChange` は `updateNoteObject(targetType, displayTargetId, obj.id, newAttrs)` であり、`skipHistory` はデフォルト `false`。

Konva の Transformer で複数オブジェクトを同時にドラッグすると、**各オブジェクトの `onDragEnd` が個別に発火する**。3 オブジェクトを同時移動した場合、`saveNoteHistory()` が 3 回呼ばれ、3 エントリが history に積まれる。Undo を押すたびに 1 エントリ分（1 オブジェクト分）しか戻らない。

### 修正対象ファイル

- `src/components/NoteView.tsx`

### 修正内容

`onChange` コールバックを `skipHistory = true` で呼び出し、`onDragEnd` / `onTransformEnd` のコールバック発火後にデバウンスで一度だけ `saveNoteHistory()` を呼ぶ。

`CanvasWorkspace` 内にデバウンス用 ref を追加:

```typescript
const saveHistoryDebounceRef = useRef<ReturnType<typeof setTimeout> | null>(null);
const debouncedSaveHistory = () => {
    if (saveHistoryDebounceRef.current) clearTimeout(saveHistoryDebounceRef.current);
    saveHistoryDebounceRef.current = setTimeout(() => { saveNoteHistory(); }, 100);
};
```

各コンポーネントの `onChange` を `skipHistory = true` に変更し、呼び出し側で `debouncedSaveHistory()` を追加:

```typescript
// NoteView.tsx の props 定義側（objs.map 内）
onChange: (newAttrs: NoteObject) => {
    updateNoteObject(targetType, displayTargetId, obj.id, newAttrs, true);  // skipHistory=true
    debouncedSaveHistory();
},
```

## 問題8: グループ解除後に個々のバウンディングボックスが表示されない

### 根本原因

グループ解除後も `selectedIds` は変化しないため、Transformer は引き続き複数オブジェクトを1つの共有バウンディングボックスで表示する。「解除された」という視覚フィードバックがない。

### 根本原因の詳細

`updateNoteObjects` で `groupId: undefined` にした後、`selectedIds` が変わらないと Transformer の `tr.nodes(nodes)` も変わらない。Transformer は依然として全選択オブジェクトを1つのグループとして表示し続ける。

### 修正対象ファイル

- `src/components/NoteView.tsx`

### 修正内容

グループ解除操作（ボタンクリック / Ctrl+Shift+G）後に `setSelectedIds([])` でいったん選択をクリアする。これにより Transformer が消え、各オブジェクトが独立した状態であることを視覚的に示す:

```typescript
// handleKeyDown の Ctrl+Shift+G ブランチ
if ((e.ctrlKey || e.metaKey) && e.shiftKey && e.key.toLowerCase() === 'g') {
    e.preventDefault();
    if (selectedIds.length === 0) return;
    updateNoteObjects(targetType, displayTargetId, selectedIds.map(id => ({ id, attrs: { groupId: undefined } })));
    setSelectedIds([]);  // ← 追加: グループ解除後は選択をクリア
    return;
}
```

ボタン経由でも同様に `setSelectedIds([])` を呼ぶ。

## 問題9: ドラッグで図形サイズが正しく変わらない

### 根本原因

`handleStageMouseMove` の shape ドラッグ処理:

```typescript
if (['rect', 'circle', 'triangle', 'image'].includes(type) && drawingNodeRef.current) {
    // ...
    drawingShapeInfoRef.current.width = newW;   // if ブロック内
    drawingShapeInfoRef.current.height = newH;  // if ブロック内
    // ...
}
```

`drawingShapeInfoRef.current.width / height` の更新が **`drawingNodeRef.current` の存在チェックの内側** にある。

`setDrawingActive(true)` は React の state 更新なので、実際の preview Rect コンポーネントのマウントは **次の React レンダリングサイクル後** になる。mouseDown 直後に素早くマウスを動かした場合、`drawingNodeRef.current` がまだ null の状態で mousemove が発火し、`width / height` が更新されないまま 0 で固定される。

mouseUp 時に `dragW >= 5 && dragH >= 5` の判定が `false` になり、デフォルトサイズで配置される。

### 修正対象ファイル

- `src/components/NoteView.tsx`

### 修正内容

`drawingShapeInfoRef.current.width / height` の更新を `if (drawingNodeRef.current)` の外側に移動し、Konva ノードの操作のみを内側に残す:

```typescript
// handleStageMouseMove 内 — 変更前
if (['rect', 'circle', 'triangle', 'image'].includes(type) && drawingNodeRef.current) {
    const startX = drawingShapeInfoRef.current._startX as number;
    const startY = drawingShapeInfoRef.current._startY as number;
    const newX = Math.min(logicalPos.x, startX);
    const newY = Math.min(logicalPos.y, startY);
    const newW = Math.abs(logicalPos.x - startX);
    const newH = Math.abs(logicalPos.y - startY);
    drawingShapeInfoRef.current.x = newX;
    drawingShapeInfoRef.current.y = newY;
    drawingShapeInfoRef.current.width = newW;
    drawingShapeInfoRef.current.height = newH;
    drawingNodeRef.current.x(newX);
    drawingNodeRef.current.y(newY);
    drawingNodeRef.current.width(newW);
    drawingNodeRef.current.height(newH);
    drawingNodeRef.current.getLayer()?.batchDraw();
    return;
}

// handleStageMouseMove 内 — 変更後
if (['rect', 'circle', 'triangle', 'image'].includes(type)) {
    const startX = drawingShapeInfoRef.current._startX as number;
    const startY = drawingShapeInfoRef.current._startY as number;
    const newX = Math.min(logicalPos.x, startX);
    const newY = Math.min(logicalPos.y, startY);
    const newW = Math.abs(logicalPos.x - startX);
    const newH = Math.abs(logicalPos.y - startY);
    // ref の更新は常に行う（drawingNodeRef の存在に依存しない）
    drawingShapeInfoRef.current.x = newX;
    drawingShapeInfoRef.current.y = newY;
    drawingShapeInfoRef.current.width = newW;
    drawingShapeInfoRef.current.height = newH;
    // Konva ノードへの反映は存在チェックの内側
    if (drawingNodeRef.current) {
        drawingNodeRef.current.x(newX);
        drawingNodeRef.current.y(newY);
        drawingNodeRef.current.width(newW);
        drawingNodeRef.current.height(newH);
        drawingNodeRef.current.getLayer()?.batchDraw();
    }
    return;
}
```

## 問題10: 図形のアスペクト比が変形後に元に戻る

### 根本原因

`ShapeObject.commonProps.onTransformEnd` で circle / triangle に対して:

```typescript
} else if (type === 'circle' || type === 'triangle') {
    const scale = Math.max(scaleX, scaleY);  // ← 強制的に正方形へ
    onChange({ width: Math.round((shapeObj.width || 100) * scale), height: Math.round(...) });
}
```

`Math.max(scaleX, scaleY)` を使うため、非均等変形（縦横比変更）をしても確定時に正方形へスナップされる。

Transformer に `keepRatio` が設定されていないため、**ドラッグ中は視覚的に非均等に見えるが確定時にスナップする** という一貫性のない挙動になる。

また `Circle` の描画が `radius=(width||100)/2` の単一 radius であるため、width と height を独立させても楕円にはなれない構造になっている。

### 修正対象ファイル

- `src/components/NoteView.tsx`

### 修正方針

2 つの選択肢がある:

**選択肢 A（推奨）: circle / triangle の Transformer に `keepRatio` を強制し、挙動を一貫させる**

`selectedObject?.type` が `circle` または `triangle` の時のみ `keepRatio={true}` を Transformer に渡す:

```typescript
// Transformer の props を動的に設定
const transformerProps = {
    ref: (el: Konva.Transformer | null) => { trRefs.current[index] = el; },
    boundBoxFunc: (oldBox: any, newBox: any) => {
        if (newBox.width < 5 || newBox.height < 5) return oldBox;
        return newBox;
    },
    keepRatio: selectedIds.length === 1 &&
        (selectedObject?.type === 'circle' || selectedObject?.type === 'triangle'),
};

<Transformer {...transformerProps} />
```

これにより circle / triangle は最初から均等スケールのみ許容され、スナップバックの違和感がなくなる。rect は引き続き自由変形可能。

**選択肢 B: width / height を独立させ、circle を楕円として扱う**

Circle を `<Ellipse>` コンポーネント（Konva）に変更し、`radiusX=(width||100)/2`, `radiusY=(height||100)/2` で描画する。triangle は `width / height` でスカラーを個別に計算する。実装コストが高い。

## 問題11: テキストオブジェクトの拡大縮小ハンドルを削除すべき

### 根本原因

`CanvasWorkspace` の Transformer 更新 useEffect で、選択された全ノードを Transformer に渡している:

```typescript
const nodes = selectedIds.map(id => stage.findOne(`#${id}`)).filter(Boolean) as Konva.Node[];
tr.nodes(nodes);
```

テキストノードも例外なく含まれるため、テキスト選択時に Transformer のリサイズハンドルが表示される。`fontSize` を直接変更するフローがある（フローティングツールバー）にもかかわらず、Transformer でのリサイズも動作してしまい混乱を招く。

### 修正対象ファイル

- `src/components/NoteView.tsx`

### 修正内容

Transformer の nodes 設定時にテキストノードを除外する:

```typescript
useEffect(() => {
    const timer = setTimeout(() => {
        [0, 1, 2, 3].forEach(index => {
            const tr = trRefs.current[index];
            if (tr) {
                const stage = tr.getStage();
                if (stage) {
                    const nodes = selectedIds
                        .map(id => stage.findOne(`#${id}`))
                        .filter((node): node is Konva.Node => {
                            if (!node) return false;
                            // テキストノードは Transformer から除外
                            const obj = objects.find(o => o.id === node.id());
                            return obj?.type !== 'text';
                        });
                    tr.nodes(nodes);
                    tr.getLayer()?.batchDraw();
                }
            }
        });
    }, 50);
    return () => clearTimeout(timer);
}, [selectedIds, objectsLength, currentCanvasIndex, isGridMode, isGridEditMode, objects]);
```

`EditableText` から `onTransformEnd` を削除し、シンプルな描画のみに戻す。テキストサイズ変更はフローティングツールバーの Size input に一本化する:

```typescript
// EditableText — onTransformEnd を削除
const EditableText = React.memo(({ textObj, onSelect, onChange, onToggleEdit, isDrawingMode }: ...) => {
    return (
        <Text
            // ...既存 props...
            // onTransformEnd を削除
        />
    );
});
```
