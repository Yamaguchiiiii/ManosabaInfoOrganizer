## §1 事件ノートが初回 Animate で表示されない（フォントゲート）

### 1-0. 調査ログ（再現・原因確定済み。再調査不要）

アプリ内ブラウザで再現した事実:

1. 事件ノート(preset)に文字オブジェクトを1つ仕込み、Note を一度も開かずに Create → Animate へ遷移。
2. Animate の事件ノート `Stage` はマウント直後から**正しい寸法で採寸されている**（例: w=393, h=262, layerScale=0.328）。→ **[[smartphone-jikennote]] §A の同期採寸(useLayoutEffect+measure)は既に実装済みで正しく効いている**。canvasSize=0 は原因では**ない**。
3. しかし Layer の子は最初 `Transformer` のみで、仕込んだ `Text` は出ない。`document.fonts.check('24px "Yomogi"')` が false の間ずっと非表示。
4. フォントのロードが完了して `check(...)` が **false→true** に変わった瞬間、`Text` が Layer に出現し表示された。

→ 決定的原因: **`CanvasWorkspace` の描画ゲート `{isFontLoaded && objs.map(...)}`（下記 L1638）が、手書きフォント Yomogi のロード完了まで事件ノートの全オブジェクト（画像・図形・矢印も含む）を丸ごと非表示にしている。**

なぜ「初回だけ」「Note 経由で直る」か:

- Yomogi は `public/fonts/Yomogi-Regular.ttf`（**約3.85MB**）を `@font-face`（`src/styles/App.scss` L10-12）で読む**大容量ローカルTTF**。
- `isFontLoaded` は **CanvasWorkspace インスタンスごとの state**（初期値 false, L204）。マウント時に `document.fonts.load('24px "Yomogi"')`（L305）で**初めてダウンロードを起動**する。
- 初回 Animate はフォントが cold → 3.85MB のDL完了（or 1.5sタイムアウト）まで空白。**Note を先に開くとそこでフォントが温まる**ため、Animate に来た時点で `fonts.load()` が即 resolve し、ほぼ瞬時に出る＝「Note 経由だと出る」。
- モバイル専用ではなく**全ビューポート共通**の症状（フォントゲートは compact/非compact 問わず通る）。

### 1-1. 修正方針

3点セットで確実に潰す:

- **(A) フォント未ロードでも全オブジェクトを描画する**（ゲート撤去）。テキストは一瞬フォールバック字形で出るが、**空白よりはるかにまし**。画像・図形・矢印はそもそもフォント非依存なので即出るべき。
- **(B) フォントロード完了時に Konva を強制再描画**して、テキストを正しい Yomogi 字形へ差し替える（フォールバック字形のまま固定されないように）。
- **(C) アプリ起動時にフォントを先読み**（App.tsx）して、Create 表示中に 3.85MB のDLを済ませ、Note/Animate に来た時のフォールバック字形フラッシュ自体を減らす。

## §3 直線/曲線/矢印/曲線矢印が Transformer で元のサイズに戻る

### 3-0. 原因（コード解析で確定）

line 系（line/arrow/curve/curve_arrow/freehand）は選択時に Transformer が付き、ハンドルドラッグで node に scaleX/scaleY が乗る。確定時 `ShapeObject.onTransformEnd`（`src/components/note/NoteObjectComponents.tsx` L162-193）の **else 分岐（L186-192）**が:

```tsx
            } else {
                onChange({
                    x: node.x(), y: node.y(),
                    scaleX: 1, scaleY: 1,
                    rotation: node.rotation(),
                });
            }
```

と、**scale を points に焼き込まずに `scaleX/Y=1` へリセット**している。結果、ドラッグ中に見えていた拡大が破棄され、元の points（＝元サイズ）に戻る。rect/circle/triangle は width/height に焼き込むので戻らない。

### 3-1. 修正方針

line 系の transformEnd で、node に乗った scaleX/scaleY（＋rotation）を **points 各座標へ焼き込んで** から scale を 1 に戻す。これで Transformer ボックスでの拡大縮小が確定・永続する。

> **注意**: §4 を実装すると line/arrow/curve/curve_arrow は Transformer ボックスを出さず端点ハンドル編集になるため、これらの transformEnd は基本通らなくなる。ただし **freehand は §4 の対象外**で Transformer ボックスのままなので、§3 の焼き込みは freehand の拡大縮小を正しく確定させるために**必須**。line 系全体の安全網としても有効なので、種別を限定せず line 系全部に効かせる。

### 3-2. 実装 — `src/components/note/NoteObjectComponents.tsx`

`onTransformEnd`（grep: `onTransformEnd: (e: Konva.KonvaEventObject<Event>) => {`, 現 L162）の else 分岐（grep: 直前が `} else if (type === 'circle' || type === 'triangle')` の後の `} else {`）を差し替える。

変更前（L186-192）:
```tsx

                onChange({
                    x: node.x(), y: node.y(),
                    scaleX: 1, scaleY: 1,
                    rotation: node.rotation(),

```
変更後:
```tsx

                // 24.md §3: line 系(line/arrow/curve/curve_arrow/freehand)は width/height を持たず
                // points で形状が決まる。旧実装は scale を捨てて scaleX/Y=1 に戻すだけで、拡大が
                // points に反映されず「元サイズに戻る」バグになっていた。scale(と回転)を points へ

                });
            }
```

## §4 直線/曲線/矢印/曲線矢印を PowerPoint 風の端点ハンドルで編集

### 4-0. 方針

単一選択された line/arrow/curve/curve_arrow に対し、Transformer のバウンディングボックスの代わりに **端点（開始点・終了点）と、曲線系では中間制御点** を白丸ハンドルで表示し、ドラッグで `obj.points` を編集する。PowerPoint の直線編集と同じ操作感。

- 対象: `line` `arrow` `curve` `curve_arrow`（**freehand は対象外**＝点数が多く端点編集に不向き。従来どおり Transformer ボックス＋§3 焼き込み）。
- line 系の points は node の (x,y) を原点とするローカル座標。回転・scale は本編集では 0/1 前提（§4-3 で Transformer 側の回転・スケールを無効化する）。よってハンドルの論理座標 = `(obj.x + points[2i], obj.y + points[2i+1])`。
- ハンドルは同じ `<Layer>` 内（＝論理座標系が一致）に描く。`name="__export_exclude"` を付け、PNG書き出し(`capturePane` が `.__export_exclude` を隠す)に写らないようにする。
- 画面上で一定サイズに見えるよう半径・線幅は `effScale` で割る（他のインジケータと同じ流儀, 例 L1773 `strokeWidth={1 / effScale}`）。

```tsx
                                            // 端点(始点・終点)は青枠白丸、曲線の中間制御点は少し小さいオレンジ丸で区別する。
                                            return Array.from({ length: pts.length / 2 }, (_, i) => {
                                                const isControl = one.type.includes('curve') && i === 1; // [start, control, end]
                                                const applyAt = (commit: boolean) => (e: Konva.KonvaEventObject<DragEvent>) => {
                                                    const absX = clamp(e.target.x(), CANVAS_BASE_W);
                                                    const absY = clamp(e.target.y(), CANVAS_BASE_H);
                                                    // クランプ後の座標にハンドル自身も吸着させる
                                                    e.target.x(absX); e.target.y(absY);
                                                    const np = [...pts];
                                                    np[i * 2] = absX - ox;
                                                    np[i * 2 + 1] = absY - oy;
                                                    const lineNode = stageRefs.current[index]?.findOne(`#${one.id}`) as Konva.Line | undefined;
                                                    if (lineNode) { lineNode.points(np); lineNode.getLayer()?.batchDraw(); }
                                                    if (commit) {
                                                        saveHistoryOnceThenSkip();
                                                        updateNoteObject(targetType, displayTargetId, one.id, { points: np }, true);
                                                    }
                                                };
                                                return (
                                                    <Circle
                                                        key={`ep_${one.id}_${i}`}
                                                        name="__export_exclude"
                                                        x={ox + pts[i * 2]}
                                                        y={oy + pts[i * 2 + 1]}
                                                        radius={isControl ? handleR * 0.85 : handleR}
                                                        fill="#ffffff"
                                                        stroke={isControl ? '#e67e22' : '#007acc'}
                                                        strokeWidth={2 / effScale}
                                                        hitStrokeWidth={18 / effScale}
                                                        draggable
                                                        onDragMove={applyAt(false)}
                                                        onDragEnd={applyAt(true)}
                                                    />
                                                );
                                            });
                                        })()}
```

補足:
- `saveHistoryOnceThenSkip`・`updateNoteObject`・`stageRefs`・`displayTargetId`・`targetType`・`CANVAS_BASE_W/H`・`effScale`・`objs`・`index` はすべて同スコープで参照可能。
- ハンドル(Circle)は draggable。ドラッグ中は line node の points をライブ更新して batchDraw、離した時に store へコミット（履歴1回）。
- ハンドルの mousedown は Stage ではなく Circle が `e.target` になるため、`handleStageMouseDown` の `if (e.target === stage)` 選択解除・範囲選択(L712-723)には**入らない**（else 分岐でメニューを閉じるだけ・現 L724-727）。よって選択は維持される。

## §5 アップロード画像の解像度が粗い

### 5-0. 原因（コード解析で確定）

アップロード/ドロップの両経路（`CanvasWorkspace.tsx` `handleImageUpload` L560-575 / `handleDrop` L577-623）は `processFile`（`src/utils/imageUtils.ts` L89-104）→ `autocropTransparent`（L28-86）を通る。`autocropTransparent` は透明縁をトリミングした後、**`maxDim = 500`（L67）で一律に縮小**して PNG 再エンコードする。結果、元画像が 500px を超える解像度は失われ、拡大表示や 2倍 PNG 書き出しで粗くなる。

補足: 画像は Blob として IndexedDB(assetStore) に保存され **state(persist の stringify) には載らない**ため、解像度を上げても [[perf-root-cause-persist]] の重さには影響しない（保存容量は増える）。

### 5-1. 修正方針

- **不透明画像（トリミング不要＝バウンディングボックスが全面）は元 Blob をそのまま保存**する（再エンコードも縮小もしない＝元解像度・元形式・元容量を完全保持）。JPEG→PNG 肥大も避けられる。
- **透明縁がある画像はトリミングするが、縮小は行わない**（`maxDim` を大きく＝実質無縮小。病的な巨大画像だけ上限 4096px で保険）。
- 表示初期サイズ（obj.width/height）は別物として**適度に抑える**：
  - クリック配置経路は既に `getImageSizeFromUrl(content, 300)` で表示300px上限に丸めているので**変更不要**（Blob が高解像度になるだけで表示は従来サイズ、拡大時に鮮明）。
  - **ドロップ経路のみ**、`processFile` が返す自然サイズをそのまま obj.width/height にしているので、表示上限を足す。

### 5-2. 実装 — `src/utils/imageUtils.ts`
